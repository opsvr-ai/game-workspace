## Context

现有系统已有订单状态机、客户管理、客户画像（`CustomerProfile` / `CustomerFollowUp`）、陪玩 KPI（约首单成功率 / 续单率 / 复购率）和财务风控，但抢单线索缺少强制追踪与名额管理。本次在既有基础上补齐「抢单名额 → 联系登记 → 追踪 → 留存/删除审核 → 异常与 KPI」闭环。

## Goals / Non-Goals

**Goals:**

- 抢单名额与门槛可配置、可开关。
- 每次联系客户必须登记结果。
- 追踪记录支持纯文字 / 纯截图 / 截图+文字，管理端可查看。
- 不消费客户持续提醒，删除需管理端审核，管理端永久留存。
- 用相对变化异常检测替代低流水预警。
- 陪玩自有微信在系统内录入，离职可交接。

**Non-Goals:**

- 不改动现有订单状态机与结算主流程。
- 不新增独立管理页面。
- 不自动判责/扣款，仅标记、提醒与人工复核。

## Decisions

### D1: 数据模型

- 新增 `CustomerContact`：记录每次联系客户的结果与证据截图。
- 新增 `CustomerTrack`：记录追踪内容（类型 `TEXT` / `IMAGE` / `TEXT_IMAGE`）。
- 新增 `CustomerDeleteRequest`：记录客户删除审核（`PENDING` / `APPROVED` / `REJECTED`）。
- 复用 `SystemConfig` 存储门槛与异常阈值。

### D2: 名额与门槛

- 「有效客户」= 联系结果为「现在打」，按陪玩 + 营业日计数。
- 三档门槛分别由 config 开关：流水门槛、每日有效客户名额、综合成功率门槛。
- 任一启用且不满足即限制抢单并给陪玩提示。
- 综合成功率 = 续单率 + 约首单成功率 + 复购率（三个百分比相加），阈值默认 90。

### D3: 联系结果

- 枚举：`NOW`(现在打) / `RESCHEDULE`(改天) / `REJECT`(不同意) / `NO_REPLY`(未回复) / `DELETED`(已删除) / `DONGGU`(懂哥) / `REFUND`(退款)。
- 抢单联系客户不占名额，但必须登记；仅「现在打」占名额。

### D4: 追踪与提醒

- 追踪类型：`TEXT` / `IMAGE` / `TEXT_IMAGE`。
- 客户不消费持续出现在陪玩端提醒列表，按最近消费与最近追踪时间排序。
- 删除申请：陪玩上传截图 → 管理端审核 → `APPROVED` 后消除提醒并在陪玩端隐藏；管理端永久保留。

### D5: 异常检测

- 以客户/陪玩为维度，用环比基线（默认近 4 周均值）对比当前周期。
- 检测流水下降、客单价档位下降、每周时长下降、每周消费下降，超过配置百分比即标记。

### D6: 位置与 KPI

- 管理端在「员工管理/陪玩管理」详情内展示该陪玩客户追踪；「客户管理」加状态筛选，不新增独立页面。
- KPI：优质客户留存率、追踪及时率、客户转化率、响应/投诉风险。

## Risks / Trade-offs

- [数据迁移] 新增表需要 Prisma 迁移 → 生成 migration，自动部署执行 `migrate deploy`，失败时回滚代码。
- [口径误报] 异常阈值不当会误报 → 阈值后台可配，且仅标记不自动判责。
- [隐私] 截图与追踪内容敏感 → 沿用 uploads 权限与角色鉴权，管理端可见、陪玩仅本人。
