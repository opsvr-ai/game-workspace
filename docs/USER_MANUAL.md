## 1. 系统概述

### 1.1 系统简介

蠢驴电竞陪玩派单管理系统是一套专为电竞陪玩工作室设计的综合管理平台。系统覆盖从客户管理、订单创建与分配、陪玩接单执行，到报账审核、收入统计的全业务流程，帮助工作室实现高效、规范的运营管理。

### 1.2 技术架构

```
浏览器 (React) ──HTTP──▶ Nest.js 后端 ──▶ PostgreSQL + Redis
                                  △
陪玩桌面端 (Electron 客户端) ──WebSocket──┘
```

- **前端**：React + Ant Design 组件库，响应式 Web 界面
- **后端**：Nest.js (Node.js)，提供 RESTful API + WebSocket 实时通信
- **数据库**：PostgreSQL 16，使用 Prisma ORM
- **缓存**：Redis 7
- **陪玩客户端**：Go 语言编写的桌面代理程序，通过 WebSocket 与服务器保持长连接

### 1.3 四种用户角色

| 角色 | 标识 | 职能概述 |
|------|------|----------|
| **老板 (OWNER)** | OWNER | 查看盈亏统计、管理客户、管理员工、管理工作室、审核客服/陪玩注册 |
| **管理员 (ADMIN)** | ADMIN | 管理所有订单、管理陪玩、管理客户、审核报账、远程控制陪玩电脑 |
| **客服 (CS)** | CS | 在派单工作台创建订单、查看订单池与陪玩状态、在「订单管理」里查自己发的单 |
| **陪玩 (COMPANION)** | COMPANION | 通过桌面客户端接单/确认/完成订单、切换工作/娱乐模式、提交报账 |

## 2. 快速入门

### 2.1 登录系统

1. 在浏览器中打开系统地址（由管理员提供）
2. 进入登录页面，页面顶部显示「蠢驴电竞陪玩派单管理系统」
3. 输入**用户名**和**密码**
4. 点击「登录」按钮
5. 登录成功后，系统会根据你的角色自动跳转到对应的工作页面

> Electron 陪玩客户端登录页支持「记住账号密码」。该功能使用操作系统级安全存储加密凭据，仅在受信任的服务端页面加载时自动填充；浏览器登录仍保持原有方式。

> 陪玩端要换账号登录时，请在右下角托盘菜单点「退出」，输入管理密码通过后客户端会同时清空登录状态和记住的账号密码；下次双击桌面「陪玩管理」会停留在登录页，可直接输入新陪玩信息。

> 客服端（客服管理）也一样：点窗口右上角 ❌ 只是**收进右下角托盘**、不退出，单子还在跑；要彻底关掉得在托盘图标上点右键 → 「退出」（左键点图标或双击则把窗口叫回来）。
> 2026-09-26 之前托盘图标因为图标文件没打进安装包而是透明的，右下角看不见它；客服端从 1.0.20260931 起、
> 陪玩端从 1.0.20260931 起都会在右下角正常显示图标（图标实在读不到时会画一个小圆点兜底，不会再“隐形”）。

> 管理端「员工管理 → 陪玩管理 → 陪玩列表」中，点击陪玩的头像或用户名会弹出「员工详情」，可直接查看该陪玩的身份证正反面。

### 2.3 页面布局说明

登录后进入主界面，分为三个区域：

- **左侧导航菜单**：根据角色显示对应的功能菜单，可点击切换功能页面。左侧菜单栏可折叠/展开（点击左上角按钮）。
- **顶部栏**：左侧显示折叠按钮，右侧显示当前登录用户名、角色标签和「退出」按钮。
- **版本信息**：客户端版本 / 前端构建 / 服务器地址统一放在「设置」页底部的「版本信息」卡片里；左侧菜单和头像上不再显示版本号与相机徽标（只有排障时才需要看）。
  登录页底部那行「前端 vXXX」也一样：**这个号是从服务端读的**（公开接口 `GET /agent/frontend-version`，不用登录就能读），
  发完版自动就是新号，不用再等人改代码；万一服务端没连上就显示上一次的兜底值，不影响登录。
- **设置中心**：所有系统设置按「钱·分账 / 派单·等级 / 陪玩端·客户端 / 门店·通知」四组排在左侧，顶部搜索框可以直接搜（如「分账」「截图」「提成」），找到就点，右侧只显示当前这一项，不用再横着一排 Tab 数过去。
- **设置项的排版**：每一条设置都是「左边名称（统一 180px 宽）、中间输入框、右边一句说明」，说明文字单独占一列自动换行，不会再把名称挤成两行；13 个设置页都是同一套排版，切页面时输入框不会再左右横跳。
- **内容区**：当前选中功能页面的主要操作区域。

### 2.4 首次设置流程

如果你是第一次使用本系统，请按以下顺序完成初始化：

1. **老板登录**：使用 OWNER 账号登录
2. **创建工作室**：进入「工作室管理」页面，创建至少一个工作室
3. **创建员工**：进入「员工管理」页面，为工作室创建 ADMIN、CS、COMPANION 角色的员工账号
4. **授权员工**：CS 和 COMPANION 角色需要授权后才能登录。进入「客户端授权」页面，找到待审核的用户，点击「审核通过」
5. **为陪玩配置客户端**：COMPANION 登录后需下载并运行 Electron 客户端 桌面客户端

## 3. 角色操作指南：老板 (OWNER)

老板拥有系统的最高权限，主要负责查看经营数据和团队管理。

### 3.1 盈亏统计

> 路径：左侧菜单 → **盈亏统计**

此页面用于查看工作室的盈亏数据，包含收入统计、支出记录和利润图表。

**操作步骤：**

1. 点击「盈亏统计」菜单进入页面
2. 系统会弹出**二次密码输入框**，请输入二次密码（默认：`888888`）
3. 验证通过后，页面展示盈亏汇总数据
4. 可切换日视图/月视图查看不同维度的统计
5. 图表区域直观展示收支趋势

> **安全提示**：二次密码验证有效期为 5 分钟，超时后需重新输入。

### 3.1.1 每日统计（客服派单 / 提成核对）

> 路径：左侧菜单 → **每日统计**

用于核对客服每天的派单量与提成，并追踪客户付款去向。

**主要能力：**
- 顶部汇总：发单总数、总金额、客服认领、未接单、已付/未付、微信/支付宝笔数
- 客服汇总：按客服展示发单数、认领数、金额、各工作室单量、陪玩费已付/未付、微信/支付宝到账
- 订单明细：展示订单号、发单客服、认领客服、工作微信、客户付款去向、收款账号、陪玩费状态与方式

**筛选：** 支持日期范围、订单状态、陪玩费状态、游戏名称筛选，点击「查询」或按回车刷新。

### 3.2 客户管理

> 路径：左侧菜单 → **客户管理**

**查看客户列表：**

表格展示所有客户的以下信息：

| 列名 | 说明 | 宽度 |
|------|------|------|
| 客户编号 / 微信号 | 一行显示「编号 · 微信号 · 昵称」，存单 / 预约用蓝字追加（**钉在表格左侧，拖到哪里都看得见是谁**） | 160 |
| 最近订单 | 最近一单：游戏名 · 金额 · 类型（机密 / 单双 / 时长在订单管理表和详情里看） | 140 |
| 来源 / 账号 | 客户来源 + 来源平台账号（账号已弃用时补一行灰字「已弃用」） | 120 |
| 状态 | 客户状态（活跃 / 跟进 / 流失 / 待开发），彩色文字、不带底色 | 72 |
| 陪玩 / 微信 | 当前分配的陪玩 + 成交时用的工作微信（未分配则显示「未分配」） | 100 |
| 跟进 / 累计 | 累计消费金额（深色）+ 最近一条跟进的时间与摘要 | 104 |
| 备注 | 备注内容（陪玩可直接在格子里填） | 104 |
| 操作 | 归属调整 / 编辑 / 删除（**钉在表格右侧，永远不会被挤出去**） | 176 |

> **「来源 / 账号」这一列只有「发单工作室的管理端」看得到（陪玩端 2026-09-29 起、接单方管理端 2026-10-02 起）：**
> 老板要求「陪玩端 隐藏 客户小红书信息」+「**除了发单工作室的管理端能看到其他人一律看不到**」——
> **来源平台 / 引流账号 / 客户昵称 / 客户账号ID** 这 4 项，现在只有**发这单的那家工作室**的客服 / 店长 / 老板
> 能看到（全站老板看全部）；**接单方一律看不到**：桥接工作室 / 线上俱乐部 / 别的店的**管理端**，以及**所有陪玩**，
> 订单列表这 4 列、客户管理对应的几列、订单详情弹窗这 4 行、客户详情页的「平台」标签一律显示「-」。
> 这 4 个字段名在 `constants/orderFields.ts` 的 `COMPANION_HIDDEN_FIELDS` 里列着，列的**字段名和顺序跟管理端是同一套**。
> 房间码、微信、二维码、YY / KOOK 这些接单要用的联系方式不受影响，接单方照常看得到。

> **重复客户档案清理（老板 2026-09-29）：** 以前「发单时丢了原客户ID」会**给同一个微信号多建一条档案**
> （线上曾出现同一个人 2~3 条）。现在客户列表顶上会自动查重：发现同一个微信号有多条时会出现一条黄条
> 「发现 N 组重复客户档案」→ 点「去合并」→ 一组一组挑「保留这条」（默认留**身上有活的那条**：
> 订单 > 跟进 > 存单，都一样就留最早的原始档案）→「合并到保留那条」。合并会把
> **订单 / 跟进 / 存单 / 接触记录 / 轨迹 / 报账单 / 客户资料**全部转到保留的那条，备注拼起来、
> 累计消费与存单相加、状态取更靠前的一个，然后删掉多余那条。这个入口只有**店长 / 老板**看得到、
> 点得动（客服看不到，避免误删客户）。合并完那一组就从黄条里消失，全部清完黄条自己消失。

> **列宽的规矩：** 上表宽度来自全局规格 `apps/web/src/constants/datasetColumns.ts`（和订单管理、
> 订单池用的是同一份）。**客户管理这些列宽是定死的**，不随窗口宽度变化、也不会被长内容挤扁；
> **订单管理（管理端）是唯一的例外** —— 它会把窗口多出来的宽度补给客户信息列（见下面「宽度预算」）。
> 窗口不够宽时**表格横向滚动，「客户编号」固定在左侧、「操作」列固定在右侧**，
> 拖到最右边看备注时也知道自己在看哪个客户、也不用往右拖表格找按钮；
> 点**整行**也能进详情。表头和正文的字号同样由这份规格统一（正文 12px / 表头 11px），
> 所以同样的数据在订单池、订单管理、客户管理里看到的大小是一致的。

> **宽度预算（为什么这些列是这么宽）：** 列宽是照**客服客户端的窗口**量的（2026-09-28 重定）：
> 客服客户端默认 1320×860、最小 1080，这时表格可用宽度只有 **991px**；1536 的屏幕上可用 **1207px**，
> 1920 上是 **1591px**。改成「一格一行」并把正文收到 12px、操作列改成一行之后，**1320（客服默认窗口）
> 就一屏放得下、不用往右拖**（客户管理 8 列共 976px）。
> **客户信息是五列（2026-09-30 起）：** 老板「你把客户账号拆分成发布订单时细分的名称不行么？比如来源：
> 小红书 引流账号： 客户昵称 客户账号id 客户联系方式，把前边的微信 挪过去」—— 原来挤在一格里的
> 客户信息现在按**发布订单表单**的字段口径拆成五列：**来源 / 引流账号 / 客户昵称 / 客户账号ID /
> 客户联系方式**。客户**微信**从原来那一列（「客户微信 / 编号」）挪进了**「客户联系方式」**
> （微信 + YY + KOOK + 房间码 + 二维码小图），客户**编号**（1~3 位）跟在「客户昵称」后面当小灰字。
> 一列只放一个字段，所以每个字段都能显示全、也能单独一眼扫过去（以前「小红书 总掉萌萌泪… ·
> 无敌的忧伤 · 609619003 · 房间…」全糊在一格里）。
> **陪玩端用的是同一份列，只是少 4 列**（2026-09-30 起）：陪玩看不到来源 / 引流账号 / 客户昵称 /
> 客户账号ID（老板 2026-09-29「陪玩端 隐藏客户小红书信息」），其余列**字段名和顺序跟管理端一模一样**
> —— 订单 / 状态 / 游戏 · 服务 / 金额 · 打单 / 客户联系方式 / 备注 / 主陪 · 副陪 / 发布 + 操作，
> 基准 **928px**。陪玩端不再自己另起一套列名（以前叫「客户微信 / 编号」+「客户账号」）。
> **同一个数据在所有页面、所有端同一套字**：字段名的唯一一份口径在
> `apps/web/src/constants/orderFields.ts`（订单管理表头 / 订单详情弹窗 / 抢单池与派单工作台那一行 /
> 客户管理 / 客户详情 / 聊天里的订单卡片全部从这一份取，陪玩端只是少几个字段），改名只改这一个文件。
>
> **订单管理（管理端）13 列不写死总宽**（2026-09-30 起）：基准 **1300px**
> （订单 66 / **状态 46** / 游戏 · 服务 112 / 金额 · 打单 74 / **来源 50 / 引流账号 116 / 客户昵称 96 /
> 客户账号ID 88 / 客户联系方式 132** / **备注 84** / 主陪 · 副陪 66 / 发布 116 / 操作 254）。
> 「备注」这一列管理端和陪玩端共用同一条（84px，2026-09-30 起），陪玩端也不再少这一列。
> **状态那一列同一天被老板连着收窄两次**：老板「状态 已抢到订单改成已被抢 无人接单改成 无人接 全部压缩到
> 3 个字，状态跟游戏之间再缩短一点，这不就有位置了」—— 状态文字一律 3 个字（客服认领 → **已认领**、
> 已抢到订单 → **已被抢**、超时退回的红字改成 **「无人接」**），列宽 72 → 50px；随后老板又说
> 「订单管理中：状态 跟游戏之间距离太大了 缩小，跟其他的最小间距一样宽度就可以」，于是收到 **46px**
> （12px 的 3 个字线上逐格量出来正好 36px，加左右各 5px 内边距 = 46px ——「状态」和「游戏 / 服务」
> 中间只剩 10px，跟别的列的最小间距一样），管理端整表基准 **1242 → 1216 → 1300px**（客户信息拆成
> 五列、管理端 / 陪玩端共用同一条「备注」列之后）。
> **这一列从此不参与窗口补宽**：窗口再宽它也不会长回去（以前它会被补到 124px 去放线上 / 桥接单的
> 「· 待反馈」小字，那一格后面就空出一大片 —— 老板指的就是这里）；那行结果小字现在放不下就省略号，
> 鼠标悬停能看到「已被抢 · 待反馈」。省下的宽度让窗口的富余变多，按补宽顺序**先补给客户那五列**。
> 陪玩端共用的「状态」列也跟着窄到 46px（陪玩端状态格里只有 2~3 个字，照样放得下），
> 陪玩端整表 1024 → 998 → **928px**（和管理端同一份列去掉那 4 列客户来源信息，另加一条共用的
> 「备注」列）。
> 窗口比这宽出来的那一段，按**补宽顺序**补给被省略号截掉的列 —— **客户那五列排最前**
> （引流账号 → 客户联系方式 → 客户昵称 → 客户账号ID → 来源），每列补到
> 「线上 120 单实测的最长内容」（引流账号 164 / 联系方式 180 / 昵称 130 / 账号ID 108 / 来源 60）就停，
> 不会再被按比例撑成空白；只有所有列都补满（窗口远宽于 1532px 时）还有富余，才按列宽比例摊给数据列。
> **操作列永远是 254px**，所以「退款」的右端就贴着表格右边、后面不留空白（老板 2026-09-29：
> 「操作的 退款后边不是还有很多空间么？不能让退款靠在最右边？让前边的客户信息全部显示出来？」）。
> 线上实测（2026-09-30，v829）：**1280~1700 的窗口状态列恒为 46px（状态↔游戏 10px）**；1920 的窗口
> 除了状态列那行结果小字（悬停看全）之外，其余 12 列全部不省略；1680 的窗口只剩 4 行昵称要省略；
> 1366 / 1536 的窗口表格可用宽度只有 1031 / 1201px，就是基准 **1300px**（横向滚动 269 / 99px）；

### 3.6 注册时照片传不上去 / 提示「Network Error」怎么办

注册要上传身份证正反面。系统**会在上传前自动把照片压缩**（长边 1600、JPEG 质量 0.82），
手机原图 4~8MB 一般会压到 100~400KB，正常网络下几秒就能提交。

如果弹窗提示「注册失败 / Network Error」，说明**这次请求根本没到服务器**（断网、或被这台电脑的
杀毒软件 / 上网保护拦了）。弹窗里会自动附上一轮自检结果：

- **纯文字请求失败** → 这台电脑网络断了，或整台机器被安全软件拦了，先检查网络再看安全软件的白名单；
- **纯文字通了、带照片那条失败** → 多半是杀毒软件的上网保护在拦上传：把 `1.117.229.36` 加入信任，
  或临时关掉「上网保护」再试；照片已经自动压过，正常网络重试一次即可；
- **照片读不出来**（弹窗会直接说原因）→ 常见两种：① 是 iPhone 的 HEIC 照片，请先转成 JPG；
  ② 照片是从手机 / 网盘 / 微信的临时目录里选的，原文件已经不在了，请先另存到电脑桌面再选。

照片实在传不上去时，登录页提供了「**先不带照片提交**」入口：先把人录进系统（仍需管理员审核），
再由店长在人员资料里补传照片。

**粘贴更快：** 注册页的「租赁合同照片」「身份证正面 / 反面」都可以不用点「选择文件」：点一下那个
虚线框，直接 `Ctrl+V` 把截图贴进来（也可以把图片文件拖进框里）；页面上只有一个照片框时，
不点它直接 `Ctrl+V` 也能粘。「个人设置」页换头像同理：点一下头像区域 `Ctrl+V` 即可。
粘贴进来的大图会自动压缩（合同按长边 2400、身份证 / 头像按长边 1600），不用先自己缩图。

> 排查留痕：前端会把这类「请求没到服务器」的失败回传到服务器 `client-errors/client-errors-<日期>.jsonl`，
> 管理员可以直接读文件定位，不用再让人反复「再试一次」。

### 4.5 进程黑名单管理

> 路径：左侧菜单 → **进程黑名单** / **进程白名单** / **杀进程日志**

功能：
- 管理陪玩终端禁止运行的软件（如外挂、竞品平台）
- 添加支持两种方式：从陪玩上报进程多选 / 手动输入
- 白名单优先于黑名单（白名单进程不被关闭）
- 22 个系统内置白名单（微信、浏览器等）

**一个开关：决定「名单要不要真的动手」**

页面顶部只有**一个**开关，归**店长自己**（老板账号不用管这一项）：

| 开关 | 谁能拨 | 关掉的意思 |
|------|--------|-----------|
| **本店黑名单是否生效** | **店长自己** | 本店名单只做记录和上报，本店陪玩一个进程都不会被结束；别家店不受影响 |

- 默认状态：**不生效**（名单只记录、不杀进程）——跟以前线上「总开关是关着的」那个状态完全一致。
- 想真动手：店长在页面顶部把开关**拨开**（开的时候会弹二次确认）。开关拨开之后，陪玩处于对应状态时，
  客户端才会按这份名单结束进程（正在玩的游戏会直接掉线）。名单是**按状态分开配**的（空闲 / 娱乐 / 休息 各一套，
  例如：空闲 → `DeltaForceClient-Win64-Shipping`、娱乐 → `python.exe`），服务端按陪玩当前状态取对应那一套下发。
- 页面顶部会直接写「**当前实际：会 / 不会结束名单里的进程**」，不用自己猜为什么没生效。
- 各店互不影响：A 店拨开只影响 A 店；B 店没拨过就还是「不生效」。

> 2026-09-24 起，以前那个**「全站总开关：自动结束黑名单进程」（只有老板能拨）已经整条去掉了** —— 老板明确要求
> 「不需要总闸，只需要店长自己定自己的俱乐部或者工作室是否生效就可以」。现在杀不杀进程只由店长自己这一个开关
> 决定；老板账号在「进程黑名单」页看到一张说明卡片，不用拨任何开关。

**按人单独设置：只给几个人动手（2026-10-02 新增）**

老板 2026-10-02：「杀黑进程 我能每台电脑单独开关么」→「按人吧 我具体给几个人打开测试一下，其他人是关闭的」。

「进程黑名单」页在本店开关下面多一张卡「**按人单独设置（哪些人的电脑会真的结束进程）**」，本店每个陪玩一行：

| 这一行选什么 | 这个人的实际结果 |
|--------------|------------------|
| **跟随本店**（默认） | 完全按本店开关走 —— 跟以前一模一样 |
| **单独开** | 即使本店开关关着，**这个人**也会按名单结束进程 |
| **单独关** | 即使本店开关开着，**这个人**也不会被结束进程 |

- 右边一列「当前实际」直接写结果（会 / 不会结束名单里的进程），不用自己推。
- 卡右上角有本店开关状态和「单独开 N 人 / 单独关 N 人」两个计数。
- 老板账号多一个「工作室」下拉（老板账号没挂工作室，要先选店再看人）；店长 / 客服只看自己店。
- **一改就生效**：保存后服务端当场把这**一个人**手里的名单重推一次，不用等客户端重连。
- 想收回来：把这一行选回「跟随本店」即可（等于删掉这个人的特批）。
- 典型用法（本来就是这么设计的）：本店开关先关着，只把要试的那几个人设成「单独开」，其他人不受影响。

2026-09-20 出过一次事故——陪玩正在「娱乐中」打三角洲，客户端重连时被系统猜成「空闲」，按空闲名单把游戏踢下线，反复掉线。
该问题已修复：客户端只在**本地确实选了娱乐中 / 休息**时才拒绝服务端「猜出来的空闲」，而且**状态和名单成对处理** ——
拒绝状态就连同一起下发的名单一起拒绝，所以不会出现「本地还是娱乐中、却套用了空闲名单」把正在玩的游戏杀掉。
（2026-10-04 又修掉相反的一面：以前客户端写死「只有本机空闲才动手」，导致娱乐中的 `python.exe` 名单根本不生效。）

**开关是「一拨就生效」的：** 改完由服务端当场重算名单并推给陪玩端（只推本店），不用等客户端重连或下一次状态切换；关掉时下发的是**空名单**，正在杀进程的客户端也会立刻停下，所以出问题可以随时一键止损。

操作：
1. 添加进程 → 选择模式 → 多选/手动输入
2. 想真的动手时，在页面顶部把「本店黑名单是否生效」拨开（默认不生效，名单只记录）
3. 推送黑名单 → 全工作室或指定陪玩
4. 终端收到后按状态执行，杀进程日志可查看历史（自动结束的记为 `AUTO_IDLE`）
5. 想停就把开关关回去 = 本店立刻停（不影响别家）

权限：名单维护（添加 / 删除 / 推送）ADMIN / OWNER / CS 均可；「本店黑名单是否生效」由**店长**自己拨；
「按人单独设置」老板 / 店长能改（老板可先选工作室），客服只能看

### 4.6 远程控制

> 路径：左侧菜单 → **远程控制**

管理陪玩电脑的远程操作，前提是陪玩的 Electron 客户端 已在线。

**功能说明：**

| 列名 | 说明 |
|------|------|
| 陪玩姓名 | 关联用户名 |
| 整体状态 | 在线/空闲/忙碌/离线 |
| PC 状态 | 电脑是否在线（绿色=在线，灰色=离线） |

**执行远程命令：**

### 4.10 工作室桥接与往来对账

> 路径：左侧菜单 → **员工管理 → 工作室桥接** → 第二个页签 **桥接往来（对账）**

**先记住桥接到底是什么**：桥接 = 两家店**互相能抢对方的单、人员互通**（本店陪玩抢得到对方店的单，
对方店的陪玩也抢得到本店的单）。桥接是**手动开的**，在「活跃桥接」页签里申请 / 同意，
共享内容（订单 / 抢单池 / 客户 / 结算 / KPI）可以逐项勾选。

**往来对账这一页解决什么问题**：单子互相接了之后，两边的钱要结清楚。系统**只统计、不自动转账**，
两个店长按这页的数在微信上定期互相结。

**怎么算的（就一句话）**：**发单店收客户的钱，接单陪玩的提成由他自己店发工资，
所以发单店要把「陪玩那一份」还给对方店。**

- **我应付对方** = 我店发的单，被对方店的陪玩接走了（我收了客户的钱）；
- **我应收对方** = 对方店发的单，被我店的陪玩接走了（提成是我店先垫的）；
- 剩下的（**工作室那份 + 客服 + 店长**那份）留在**发单店**。
- 金额 = 该陪玩这笔单的业绩 × 他的分成比例；比例按**陪玩自己店**的阶梯、按他**当月总流水**落档，
  和月末发工资用的是同一套数。所以两个人分账时不会出现「系统算的和实际发的不一样」。
- 一单两个人打（双陪）：搭档只按他那份金额算；只参与分成的人（分成栏）也按他那一段算，
  不会把整单都算给对方店。

**页面上怎么用**

| 区域 | 说明 |
|------|------|
| 月份选择 | 按**营业月**（每日 12:00 换日，和报账、结算同一个口径）。默认当月，可回看任意月份 |
| 全部桥接工作室 | 只跟某一家店对账时选它，账就只剩这一家 |
| 三张卡 | **我应付对方** / **我应收对方** / **净额**（净额正 = 对方该给我，负 = 我该给对方） |
| 按工作室分开算 | 一家店一笔小账：应付多少、应收多少、净额多少、各几单 |
| 明细表 | 逐单：完成时间、方向（我付 / 我收）、单号、游戏、客户、接单陪玩（含他所属店与角色）、业绩、比例、**应给对方的钱**、发单店留下 |
| 复制明细（发微信） | 一键把「汇总 + 逐单明细」复制成文字，直接粘到微信发给对方店长 |

**结账怎么走**：看净额 → 点「复制明细」发给对方店长 → 微信上转一次差额 → **不用在这页改任何数据**
（这页是只读的，改了也不会影响工资、余额或订单）。

**注意**

- 这页**只统计**，不会自动扣钱、也不会往任何人余额里加钱；发工资仍然按结算流程走。
- 桥接单**不算本店店长的分成**（两边都不算），这是刻意的口径。
- 断桥接不会删掉历史单：以前接过的单仍然留在这页的往来里，方便继续对旧账。

### 4.11 客服提成 · 今日看板 + 客服档位（老板 / 店长）

  待反馈的不进分母）。
- 中间四张卡：线下（单数 + 流水 + 提成）/ 桥接（本月单数 + 提成）/ 线上（单数 + 提成）/
  桥接达标（本月）；下面还有 **今日应发合计（全体客服）** 和 **今天「不成功」的原因排行**。
- 明细表每人一行：发单、派出、线下、桥接（本月）、线上、成功/不成功/待反馈、成功率、应发提成、
  底薪(日)、**今日应发**、当月累计。**点一行**出右侧抽屉，看这个人今天发出的每一张单（渠道、客户、陪玩、
  金额、结果、原因），里面还能直接「记结果」。
- 老板 / 店长点谁都行；**客服点别人那一行不会有明细**（后端只给本人），自己那一行点得开。
- **「桥接（本月）」这一列按本月看**：本月跑了多少单、现在单价几元/单、再跑几单能升到 3 元 / 5 元；
  「今日 N / 目标」只是进度显示（老板 2026-09-30：「这个我建议别这样了，扣底薪客服会不愿意的」）。
  **跑不够只影响单价，底薪照发全额、提成也不打折。**
- 「达标」的统计口径：**只排除明确不成功 / 退款 / 取消**的单，接单方还没反馈的**照算**
  —— 对方没回话不该算客服头上。这一页和月底结算、工资生成用的是**同一套口径**，不会出现
  「看板一个数、工资另一个数」。

**客服档位（每人的默认派单范围 + 底薪）**

「客服设置」页最下面那张表，一行一个客服：

- **默认派单范围**：`线下→线上流转`（默认）/ `线上→线下流转`。这只决定**他发单时「入池方式」的默认值**，
  发单时还能单独改（见 §5.4）。
- **底薪（月）**：留空 = 用「工资规则」里客服那一个统一数；填了就按这个人的数算
  （今日看板的「底薪(日)」、月度结算、工资生成都会跟着走）。改完点这一行的「保存」。
- **提成**：点「单独一套」能给这一个人单独定提成（线下比例 / 保底 / 封顶、桥接单价与 3 元·5 元阶梯门槛、
  线上口径与单价）。**留空的项还是用本店那一套**；弹窗里的「清空（回到本店一套）」= 这个人回到本店的口径。
  行上的小标签会写清楚他现在是「单独一套」还是「用本店」。（老板 2026-09-30：「孙也照用，还是他单独一套？」）

**客服的钱怎么算、在哪儿填（老板 2026-09-30「这些我自己填写」）**

一条公式：「当月应发 = 底薪（**永远全额**）+ 线下提成 + 桥接提成 + 线上提成 +
全勤奖 − 迟到 / 缺勤 / 早退扣款」。桥接跑不够**不扣底薪**，只是单价停在第一档。
每个数字都能自己填，位置就在 **设置中心 → 客服设置**
（`/admin/cs-settings`）和 **设置中心 → 工资规则**（`/admin/payroll`）：

| 公式里的一项 | 怎么算 | 在哪儿填 |
|--------------|--------|----------|
| 线下提成 | 每张成功线下单 max(流水 × 「线下提成比例」, 「线下保底」)，填了「线下每单封顶」才封顶 | 客服设置 → 客服提成 → 线下 |
| 桥接提成 | 成功桥接单数 × 阶梯单价（月 < 最低单数按「桥接每单提成」，达到 3 元 / 5 元门槛按「阶梯单价」） | 客服设置 → 客服提成 → 桥接 |
| 线上提成 | 二选一：**按流水比例**（默认，每单 = 流水 × 「线上流水比例」）或 **按成功单数 × 每单单价**（用「线上每单单价」，双陪算 2 单） | 客服设置 → 客服提成 → 线上俱乐部的「线上怎么算」下拉 + 下面两个数 |
| 底薪 / 月休 | 「工资规则」里客服那一行；想给某个人单独定，用「客服设置」最下面那张档位表（留空 = 用统一数） | 工资规则 / 客服设置 → 客服档位 |
| 桥接单价阶梯 | **桥接唯一的口径**：本月 < 最低单数按「桥接每单提成」，达到 3 元 / 5 元门槛按「阶梯单价」。跑不够只影响单价，**不扣底薪、不扣提成** | 客服设置 → 客服提成 → 桥接 |
| 每日桥接目标 | 看板上标「今天够了没有」的进度统计，**不参与算钱** | 客服设置 → 每日桥接目标 |
| 全勤奖 / 迟到 / 缺勤 / 早退扣款 | 按考勤记录算：缺勤 × 日薪 + 迟到 × 每次扣款 + 早退 × 每次扣款；满勤给全勤奖 | 工资规则（客服那一行） |

- 「线上怎么算」两个数都填也只按选中的那一种算，**不会叠加**；没改过就还是 2026-09-29 定的按流水比例。
- 双陪的单（有搭档、或备注写了「双」）线上线下都**算 2 单**。
- 客服自己、店长、老板都能在「客服提成 · 今日看板」上看到这一页的实时估算（点一行看逐单明细）。
- **算哪些单**：默认**只算首单**（跟以前一模一样）；续单 / 复购 / 打赏多是陪玩自己维护的，要算就打开
  「客服提成」卡里的那个开关。

**「催一下」+「今天我们店接的单」（老板 2026-09-30 补的两块）**

- **催一下**：线上 / 桥接单派出去以后一直没人反馈结果，就是「待反馈」。在明细抽屉里对那张单点「催一下」——
  系统记下「催过几次、最后一次什么时候」，同时给**接单工作室**（桥接店 / 线上俱乐部）的客服 / 店长推一条
  提醒（右下角弹一下；对方正开着这一页也会自动刷新）。已经反馈过结果的单不用催，本店线下单也不用催
  （陪玩点「开始首单」就自动算成功）。
- **今天我们店接的单**（同一页最下面那张表）：给桥接店 / 线上俱乐部看的 —— 今天**别人家的单被我们店陪玩
  接了多少、成功多少、不成功多少、还有多少没反馈**，还有「被催过几单」。一行一张单：渠道 / 发单店 /
  接单陪玩 / 客户 / 金额 / 结果 / 催过几次；待反馈的单旁边直接就能「记结果」，不用回订单管理翻。
  结果栏里还会写「某某 记」—— 谁记的、哪单、什么原因都留痕。

### 4.11 机器管理：所有客户端电脑都能远程查看 / 一键诊断

老板 2026-09-30 定的规矩：**客服电脑、陪玩电脑、以后新来的每一台，都要能被远程查看、能一键诊断**，
机器一出问题不用再等人到电脑跟前。入口：左侧「设置中心 → 客户端与设备 → **机器管理**」（店长 / 老板可见）。

**为什么不是「远程桌面连过去」？** 这些电脑都在各自的局域网里（`192.168.1.x` 之类），云服务器直连不进去。
所以走的是反过来的一条路：**电脑主动往服务器报**。客户端每 5 分钟报一次「我是谁」（计算机名 / MAC / IP /
Windows 账号 / 登录账号 / 客户端版本），每 60 秒领一次服务器派给它的任务，执行完把结果传回来。
好处：不管客服 / 陪玩在什么网络、有没有公网 IP 都能用，也不用在被控电脑上开任何端口。

**页面上一台电脑一行，看得到：**

| 列 | 说明 |
|----|------|
| 状态 | 绿「在线」= 客户端 5 分钟内有上报；灰「离线」= 客户端没在跑 / 关机 / 断网 |
| 这台电脑 | 计算机名、类型（客服端 / 陪玩端）、使用人、Windows 账号。带「旧版客户端」标记的行还没上报过机器信息 |
| IP / 网卡 | 主 IP、其它网卡、MAC（MAC 是认机器用的，换 IP 也认得出） |
| 版本 | 这台机现在的客户端版本号，下面一行是**看门狗版本**（看门狗负责自动更新和远程任务；落后云端会标红「待自动更新」，会被自动补上） |
| 远程管理 | 已开通 / 未开通；已开通的会显示运维账号和**口令（可直接复制）**。没开通的会被**自动开通**（服务端一发现就补一条任务，不用有人点） |
| 最后上报 | 几分钟前 / 几小时前 |

**页面分两组，统计只算真机器（2026-10-01 老板要求）：**

上面三个数（真机器 / 在线 / 已开通远程管理）**只算有客户端在报机器信息的机器** —— 这才是
「有几台电脑归我们管、几台已经能远程连」的真实答案。下面单独一组「开不了远程管理的记录」放的是
没有机器信息的行：以前手工登记的电脑（那会儿还没装客户端），或只登记了版本号、没有机器指纹的旧记录
（同一使用人已经有真机器在上报的，就直接不重复列了）。这一组一行一句写明为什么开不了，按钮全是灰的，
也不进上面的统计 —— 免得看着像「很多人没开远程管理」。等那台电脑上的客户端把机器信息报一次，
它就会自动挪到上面真机器那一组。

**三个动作：**

1. **一键诊断** —— 点一下，服务器把诊断脚本排进队列，那台电脑 1 分钟内领走执行，报告自动传回来。
   报告 12 项：机器与系统、磁盘空间、网络（IP / 网关 / DNS）、**到服务器的连通性**（ping + TCP + 接口自测）、
   客户端进程与服务（含看门狗 SystemHelper）、安装目录与注册表里的版本、客户端日志尾部、系统 / 应用事件日志
   最近 24 小时的报错、**蓝屏与异常关机**（41 / 1001 / 6008 + `C:\Windows\Minidump`）、远程管理账号状态、
   **代理 / VPN / 加速器迹象**（这是客服端「连不上服务器」最常见的原因）、当前网络连接。
   点「查看记录」能看到这台机器的历史任务，点「看报告」看全文。
2. **开通远程管理** —— 在那台电脑上建（或修）运维账号 `chunlvops`：加入管理员组、**密码永不过期**、
   打开 `LocalAccountTokenFilterPolicy` 与文件共享 / 远程服务 / WMI 防火墙。**每台机器一个独立口令**，
   建完把账号口令回传台账（页面「远程管理」列直接可见），同时在那台机 `C:\ProgramData\chunlv\remote-account.txt`
   留档一份。新装的机器安装时自动做这一步，不需要再点。
3. **下发指令** —— 在目标电脑上以 PowerShell 执行一条指令，输出传回来（只读排查用）。
   例：`Get-Process | Where-Object { $_.ProcessName -like "*客服*" } | Select-Object ProcessName,Id,StartTime`。
   **发之前自己看清楚**：这是直接在别人的电脑上执行。

**没有客户端也能救急：** 让客服 / 陪玩在那台电脑上双击这两个链接之一，点一下「是」给管理员权限就行 ——

- 一键诊断：`http://1.117.229.36:3001/uploads/客户端诊断.bat`（跑完报告直接传回服务器，页面里就能看）
- 一键开通远程管理：`http://1.117.229.36:3001/uploads/开通远程管理.bat`

**注意两点：** 「离线」的电脑也可以点诊断 —— 任务会挂在队列里，等它上线（客户端起来）自动执行。
带「旧版客户端」标记的行暂时只能看版本和在线状态，等它的客户端自动升级到新版（客服端 `1.0.20260933` /
陪玩端 `1.0.20260932`）就能诊断了。

**这些任务现在由「看门狗」以系统权限执行（2026-10-01 起）。** 以前是客户端去执行，登录的 Windows 账号
不是管理员就白派（叶号那台就是这么失败的）。看门狗是随机器开机的系统服务，它来跑任务，
没人登录、登录的是普通账号、机器锁屏都能干。任务表里「谁点的」显示紫色「自动」的，就是服务端发现
这台机器缺东西（远程管理没开通 / 看门狗不是最新）自己补的，下面会写补的原因。
**看门狗自己也会跟着云端升级**（每 30 分钟看一次，只重启看门狗服务，不打断正在接单的陪玩），
所以「换看门狗」这件事以后不用再让人跑到电脑跟前。
### 4.12 陪玩工作微信：陪玩自己填，管理端审核（老板 / 店长 / 客服）

以前是管理端替陪玩建号、绑号；现在陪玩可以自己填，**但要管理端审核通过才生效**（老板 2026-10-02）。

- 陪玩在「我的工作微信」卡片里填一个号提交后，你在「工作微信 → 陪玩工作微信」页的**同一张表最上面**
  就能看到这几行（橙色底、状态「待审核」），有新的提交还会弹一条提醒（并进右上角通知中心）。
  **页面只有这一张表**（老板 2026-10-02：「现在是上下两部分，合并成一整块，要不然很乱」——
  以前审核归上面一张单独的卡片、工作微信归下面一张表）：等审核的排在**最上面**，
  下面紧接着就是已经生效的工作微信行；卡片顶部还有一条红字「N 条陪玩提交待审核」。
  等审核那几行的「绑定对象」写的是**谁提交的**（老板还能看到是哪家工作室），
  「操作」列就是**通过 / 驳回**。
- 每条申请可以**通过**或**驳回**：驳回可以写原因，陪玩那边能看到；通过 / 驳回都会记谁审的、什么时候审的。
  处理完这一行就从表里消失 —— 通过的号**当场变成下面那行「已绑定」**（就是他现在的号）。
- **只有点「通过」才会生效**：通过后系统把这个号绑给他（他原来绑的号自动退下来），抢单判重立刻按新号算。
  **审核通过之前，他那边用的还是现在的号** —— 所以陪玩想换号可以随时提交，不会出现「换到一半没号用」。
- 点「通过」时会校验：这个号如果已经绑给别的陪玩、被客服占用、或者是「客服工作微信」类型的号，
  服务端会拒绝并提示，不会把两个人都绑到同一个号上。
- 管理端原来的「添加微信号 / 绑定陪玩」都还在，你也可以照旧手动建号、手动绑。
- **谁都能审**：**老板 / 店长 / 客服**三个角色的左边栏都有「工作微信 → 陪玩工作微信」入口，进去都能审。
  **店长和客服只看自己店的提交**（不会看到别人家工作室的）；**老板是全站可见** ——
  所有店的提交都在同一张表里，等审核那几行的「绑定对象」后面会跟上是哪家工作室。
- **客服也能看到本店的陪玩工作微信列表**（老板 2026-10-03 报「邵泽慧怎么不显示陪玩的微信列表？」）。
  以前客服点开这一页是**空的**：服务端把客服的列表一刀切成「只看绑给自己的**客服**工作微信」，
  陪玩那一栏自然一条都没有。现在：**「陪玩工作微信」= 本店全部都能看**（客服本来就要在这张表上审）；
  **「客服工作微信」仍然只看绑给自己的那些**（不会去动别的客服的号）。客服也能改本店陪玩微信的备注、删号。
- **客服换工作微信要店长同意（2026-10-05 起）**：**绑 / 解绑「客服工作微信」只有店长 / 老板能做**，
  客服本人在这一页是只读的（没有绑定 / 解绑按钮）。客服要换号，把新微信号发给店长，让店长在这里改。
  陪玩提交的微信号申请，客服照旧可以审（那条是绑给陪玩的，客服自己占不到）。

### 4.13 实时看板（老板 / 店长 / 客服，2026-10-03 起；陪玩端 2026-10-04 起另见 6.3.5）

> 路径：左侧菜单 → **派单管理 → 实时看板**

老板原话：「谁跟谁在接单中、谁谁娱乐中、谁谁空闲中，也显示正在打什么游戏、打了多久等等，
让管理端派单的时候也方便，一目了然，不用挨个问。」

- 顶部 5 个数：**接单中 / 娱乐中 / 空闲 / 休息 / 离线** —— **点一下只看这一类，再点一下看回全部**。
- 下面是「**一人一格**」的网格（像网吧管理系统的机位图），按 **接单中 → 娱乐中 → 空闲 → 休息 → 离线**
  的顺序从头排到尾，一眼扫过去就知道谁在忙、谁闲着。
- 打单中那一格写清：在打什么游戏、**跟谁一起打**（主陪 / 搭档 + 对方名字）、
  **已经打了多久**（按秒走字，不用手动刷新；数据 15 秒自动拉一次）、单号、客户**编号**、
  **本单多少钱**、**今天已经多少业绩**。
- 每格底部是这个人今天的情况：**今日业绩**（今天已完成单里他应得的部分，口径和结算 / 报账一致）
  + 今日单数 + 今日接单时长。
- **在线口径**：那台电脑 2 分钟内有心跳才算在线（人离开、关机、断网一会儿就会掉到「离线」）。
- **有活跃订单、但客户端掉线的人，仍然留在「接单中」**（订单还在跑，不能把人藏起来），
  这一格会标 **「⚠ 客户端已掉线（这单还在进行）」**；离线统计里不再重复算他。
- **看板只有客户编号，没有客户微信** —— 它的用途是派单，不是看客户资料。
- **桥接工作室的人也一起显示（2026-10-04 起）**：店长 / 客服 / 陪玩 看到的都是 **本店 + 桥接工作室**
  （老板：「方便蠢驴电竞线下找不到人的时候可以邀请桥接工作室的陪玩」）。桥接的人那格会标
  **🌉 桥接 · 工作室名**，且**只给订单信息**（在打什么、跟谁、多久、单号），**不显示挣了多少**。
- **陪玩端也有这块看板**（`派单管理 → 实时看板`）：能看到本店同事和桥接工作室的人在忙什么、谁快打完了，
  好提前约人；但**金额只有自己那一格显示**，别人一律「🔒 业绩不公开」（详见 6.3.5）。
- 右上角「刷新」可以立刻拉一次，不用等那 15 秒。

### 4.14 客户看板：每个客户花了多少、现在跟谁在打（老板 / 店长 / 客服，2026-10-03 起）

> 路径：左侧菜单 → **客户管理 → 客户看板**

老板原话：「罗列所有的客户，每个客户的消费情况 + 是不是正在跟陪玩打游戏，消费金额或者游戏时长或者正在跟陪玩打的排在最上边……
让所有人都能一目了然知道自己的陪玩或者自己的客户到底什么样。」

- 顶部 6 个数：**客户总数 / 正在打 / 今日消费 / 累计消费 / 累计时长 / 陪玩数**（还有「未分配」客户数）。
  今日消费按**营业日**算（当日 12:00 至次日 12:00），跟「实时看板」的今日业绩是同一条时间界线。
- **每一行是一个客户**，写清：客户编号 + 状态、归谁（陪玩头像 + 在线点 + 状态）、**现在在干什么**
  （正在打的红点闪烁：游戏名 + 单号 + 已经打了多久 + 主陪 / 搭档；没在打就写最近一单）、
  **消费金额**（只算**已完成**的单，和盈亏统计 / 报账同一个口径）、**今日（营业日）**一列（今日消费金额 + 今日单数 + 今日时长）、
  **完成单数**、**累计时长**（已完成会话的时长之和）、最近一单时间。
- **排序默认「正在打优先」** —— 正在打的排最上边，然后按消费金额、再按时长；
  右上角也能切成「**今日消费** / 累计消费 / 游戏时长 / 最近下单」。
- 上面一排**陪玩小卡**：点一下只看这个陪玩的客户，再点一下取消；也可以切「总表 / 按陪玩分组」看每个陪玩的客户盘子和消费。
- **客户微信默认打码**（`••••••`，看板经常挂在墙上），右上角「显示微信号」开关可以展开 ——
  店长 / 客服 / 老板本来就该看到客户微信（等同「客户管理」）。
- **陪玩看到的不一样**（2026-10-04 起）：陪玩端同一块看板**只看得到自己的客户**，而且做成了**进度条排行榜**——
  一个客户一条进度条，按「累计消费（默认）/ 今日消费 / 游戏时长」**从高到低**排，条形越长 = 数值越高，前三名带奖牌，
  点任意一行直接进客户详情；同样**看不到客户是从哪个平台 / 哪个引流账号来的**（那是发单工作室管理端的信息）。
- 数据 15 秒自动刷一次，正在打的秒数按秒走字，不用手动刷新。

#### 4.14.1 客户画像：这个客户在几个工作微信上、爱打机密还是绝密（2026-10-04 起）

> 路径：管理端客户看板 → 客户那一行的「**画像**」按钮（客服 / 店长 / 老板，看完整版）。
> 陪玩端客户看板同一行是「**客户喜好**」按钮 —— **只写这个客户自己的喜好**（爱打机密 / 绝密、习惯单价、
> 成交单数 / 时长 / 消费），**不显示「跟谁打过」**：没有工作微信明细表、没有经手人、没有推荐陪玩，
> 也不标「N 人打过」。服务端给陪玩的画像里根本不含这些字段，前端绕不过去。

老板原话：「这同一个客户在多少个工作微信上，各自消费了多少、打机密还是绝密、打了多久、维护多久了，
不就能评判这个客户喜欢什么样的陪玩、喜欢什么样的单价等信息了，以后再遇到这个客户咨询小红书，
客服不就应该单独派给什么样的陪玩了。」

- 打开抽屉，**最上面一行就是结论**：「这个客户一共成交 N 单、打了 X 小时、毛收入 Y 元，在 K 个工作微信上打过，
  最常打「绝密/机密」（占百分之几）；习惯单价 A~B 元/小时。优先派给 XXX（工作微信 …）：他陪这个客户打过 …」
  —— 客服拿到这个客户的新咨询，照这一行派单就行。
- **「这个客户在 N 个工作微信上」一张表**：一个工作微信一行，写清各号上的 **单数 / 打了多久 / 消费 / 机密·绝密各多少 / 
  习惯单价 / 维护多少天（最近一次是几天前）/ 这个号现在在线还是离线**。双陪的单会把**主陪 + 副陪**一起列在该号下面，
  副陪那份流水也照样算进去（不会漏）。
- 表里同时给出**头部 3 个推荐陪玩**小卡：谁最该接、陪他打过多久该打什么模式、现在是不是空闲、工作微信是多少。
  （以上明细表与推荐小卡**只有管理端**能看到；陪玩端只有「客户喜好」。）
- 口径提醒：**只算完成的单**（和客户看板的「消费金额」、盈亏统计同一条线）；消费 = **单价 × 实际时长**，
  主陪、副陪各算各的；「常打机密还是绝密」优先看**陪玩自己确认的模式**，没有才看客服发单时填的。
- 工作微信这一栏：**单上记了就用单上的号**（陪玩抢到这单时自动绑的）；老单没记，就退回这个陪玩当前绑定的号（会标注「按绑定号」）；
  连绑定号都没有，这一行就写「未绑定工作微信」，但人和单照样列出来，不会消失。
- 客户微信默认打码，跟着看板右上角「显示微信号」开关一起变。
- **可见范围**：管理端看完整画像（客服 / 店长看本店、老板全站）；陪玩只能看自己名下客户的「**客户喜好**」，
  看不到任何经手人 / 工作微信 / 别人的收入。

### 4.15 客户一直没通过怎么办：待办提醒 → 小红书问 → 封存（2026-10-04 起）

> 背景（老板原话）：「客户真通过了、要打单，陪玩必须点添加成功才能在客户管理里找到这个客户、点开始首单；
> 他要是真忘记，系统会定期提醒他。除非真的好几天客户都没通过，那就是客户真的不通过了，这时候管理端给对应删除这个客户即可。」

- **不扣名额、不自动收回**：抢到单只是提醒，次数照旧（抢单即扣、客服同意补单 +1）。
- **陪玩本人**：抢到单后一直没点「添加成功 / 添加失败」，系统只在 **满 24 小时、满 7 天** 各提醒一次，共两次
  （右下角横幅，全屏打游戏也压在最上层，**点一下直接跳到订单管理**）。积压很久的老单只弹一次，不会一次弹好几遍；
  这单只要已经进入服务（有服务会话），就不再催。老板 2026-10-04 简化口径：「别搞这么复杂，先 24h 提醒一次，后期直接 7 天提醒一次。」
- **客服 / 店长 / 老板（待办）**：只在**满 7 天**时进一条**待办**（右上角铃铛，带红点角标，不弹窗打扰），
  按工作室汇总成一条，写清「订单号 + 哪个陪玩 + 客户微信号 + **来源平台 / 小红书账号**」，点一下进「客户管理」。
  老板 2026-10-04 的口径：「去对应的小红书找到该客户、通过小红书去问问客户、看看客户回不回，才能定。」
- **人工决定：先去小红书私信问客户，客户也不回就「封存」**（不自动收单、不扣名额、不删档案）：
  - 客户管理列表上方切到「**活跃客户 / 已封存**」；行尾「**封存**」→ 填不填原因都行，档案 / 订单 / 流水 / 跟进记录全保留，
    只是从活跃客户里收起来（客户看板也不再显示）。「封存」只有店长 / 老板能点。
  - 以后想再试一次：在「已封存」里点「**解封**」，可以顺手**换一个陪玩**再让他加一次微信
    （解封 / 改派会自动往备注里追加一行 `[解封重试 时间] 改派给 XX`，方便回头看谁试过）。
  - 客户确实不再合作、要彻底删掉时才用「删除」：名下只有「从未成交」的单可以连单一起清掉（以前有单就删不掉）；
    只要有一单成交 / 有流水 / 有服务会话 / 有补单申请，系统**直接挡住**，账目不动（真要处理找老板）。
- 陪玩也可以自己点「添加失败」：会自动生成补单申请走「订单管理 → 补单审核」，管理端同意后次数 +1，另一条路。

## 5. 角色操作指南：客服 (CS)

客服是派单系统的核心操作者，负责创建订单和跟踪订单状态。

### 5.1 派单工作台

> 路径：左侧菜单 → **派单工作台**

派单工作台分为三栏布局：

> **别人家（桥接工作室 / 线上俱乐部）发来的单，来源那几列一律显示「-」（2026-10-02）：** 订单池 / 订单管理里
> 混着别家发来的单，这些单的 **来源平台 / 引流账号 / 客户昵称 / 客户账号ID** 4 列对你也是「-」——
> 只有**发这单的那家工作室**的管理端看得到（全站老板看全部）。你自家发的单照常看得到；
> 房间码 / 微信 / YY / KOOK 这些接单要用的联系方式不受影响。

#### 左栏：陪玩状态

实时显示当前工作室所有陪玩的状态：

| 状态 | 标签颜色 | 说明 |
|------|----------|------|
| 在线 (ONLINE) | 红色 | 陪玩在线但未设置为空闲 |
| 空闲 (IDLE) | 绿色 | 陪玩空闲，可接收订单 |
| 忙碌 (BUSY) | 金色 | 陪玩正在处理订单 |
| 离线 (OFFLINE) | 灰色 | 陪玩未登录客户端 |

列表每 10 秒自动刷新。

#### 中栏：订单池

显示所有待派发的池子订单（POOL 模式、状态为 PENDING）。

每个订单卡片展示：
- 游戏名称
- 订单类型标签（新单/续费/复购/打赏）
- 客户微信号
- 订单金额
- 「指定陪玩」按钮
- 「自己抢单」按钮（客服/管理员/老板可见）

> 订单池也是每 10 秒自动刷新。

> **找单/找人**：订单池左上角有一个搜索框，一个框就能搜 —— 客户微信、小红书（来源账号）、来源平台、
> 客户昵称、平台账号 ID、客户编号、房间码、YY / KOOK、客服备注、派单人、接单陪玩、游戏名。
> 用空格隔开多个词就是「同时满足」（例如 `小红书 shun`）。右边有筛选时显示「筛选结果 N/M」。
> **派单记录面板已删除，改去「订单管理」**：派单工作台底部原来还有一块「派单记录」面板
> （客服看「我发布的订单」、店长看本店、老板看全部工作室），2026-09-27 起已经整块删掉，
> 功能全部搬进左侧菜单的 **订单管理**（同一个搜索框、按派单人筛选、客户账号明细都在那边），
> 派单工作台只留订单池，界面更干净。

> **空的时候只占一行**：没人发单时订单池只显示一行虚线提示，不会用一张大插画把桌面占满。

> **陪玩端订单池可以收起左侧「人员」**：右上角「隐藏人员 / 显示人员」一键切换，收起后订单池多出 246px 宽度，
> 选择会被记住。要在群里喊人、找客服，点左侧菜单的「群聊」即可。

> **人员列表一行看什么**：第 1 行是「段位图标 + 名字 + 💬（私聊）」，第 2 行是「● 状态 + 角色 / 工作室」，
> 正在打单的还会跟一条蓝色的「任务类型 · 游戏名」。名字在 246px 的列宽里完整显示，
> 特别长的才会用省略号收尾，鼠标悬停可看全名。

> **超时订单**：立即打订单超过 10 分钟、预约订单超过 60 分钟仍无人抢时，系统会将其从陪玩订单池隐藏，转入客服/管理端的「订单池流转失败明细」。陪玩端不会再看到这些单，也不能抢；由发单客服在流转失败明细里再次发布或标记处理完成。

> **流转失败明细的顺序**：已流转失败的单排在前面，同一批里**新的在最上面**（2026-09-27 起）。
> 以前是老的排最前，刚失败的单会被几十条旧单压到最后一行，容易以为「没进去」。
> 另外，一行里**看不到「主陪」名字、状态又是红色「无人接」**的，就是这单发出去到超时都没有陪玩抢，
> 不是系统没记录谁接的。**2026-10-02 起**：客服已经接手跟进这张单（在「管理端直添客户流转明细」里
> 记过「添加情况」、或是管理端直添登记进来的客户）之后，这里**不再写「无人接」**，改按订单自己的状态走
> （还在等派 → 待派单）—— 免得跟同一行的「已添加 / 还没派出去」打架。

> **另外两张列表长得和「订单管理」一模一样**（2026-09-28 起）：流转失败明细 / 流转明细
> 这两张列表以前是卡片行（一格叠 2~3 行、十几个彩色标签、按钮单独占一行），现在换成和订单管理
> **同一张表**：同样是「订单 / 状态 / 游戏服务 / 金额打单 / 客户微信编号 / 客户账号 / 发布」这几列
> （顺序与宽度完全一致），外加一个这一页特有的**「说明」列**（退回情况 / 收款情况）和钉在右侧的操作列。
> 一格一行、行高 33px、状态只用彩色文字，长了自动省略号、鼠标悬停看全。

> **「直接派单」= 客服养好的客户正式派出去（2026-09-29 修）**：从「管理端直添客户流转明细」点
> 「直接派单」发出去的新单，会标成**「客服养好的客户」**，并且带上原单号与原客户ID ——
> 之后被谁抢走、陪玩用什么微信、钱到哪了，都在「管理端直添客户流转明细」里看得到
> （以前这一步没把标记写上去，流转明细**一直是空的**）。同一次也修掉了「发单丢原客户ID、
> 同一个客户被重复建档案」的问题（线上已出现过同一个人 2~3 条客户档案）。
> 从「订单池流转失败明细」重新派单不算养客单，行为不变。

> **「客服跟进台账」已并进「管理端直添客户流转明细」（2026-09-30 起）**：以前是两页 ——
> 「客服跟进台账」（还没派出去的）和「管理端直添客户流转明细」（已派出、陪玩接了的），同一批客户
> 在两个页面上各显示一遍、列法还不一样（老板：「显示的不一样 显得乱七八糟的」）。现在**只剩一页**
> 「管理端直添客户流转明细」：客户信息还是订单列表那**五列**（来源 / 引流账号 / 客户昵称（带编号）/
> 客户账号ID / 客户联系方式，和订单列表共用同一份，客户信息在哪儿都长一个样），后面接
> **工作微信 / 添加情况 / 最后跟进 / 下次跟进 / 收款情况 / 操作**。怎么用见下面
> 「管理端直添客户流转明细」一节。

> **列表空的时候也不会白板**（2026-09-28 起）：这几页各自都是派单管理里的一个标签页，
> 以前有的页一条数据都没有时整页是白的（别的页却有「标题 + 表头 + 暂无…」），
> 容易被当成页面坏了。现在几页统一：标题、搜索框、表头都在，中间写「还没有直添客户流转记录…」
> 这类提示，一眼能分清「今天没有要跟进的」还是「出问题了」。

> **每条订单的时间**：表里的「发布」列写的是「发布人 + 发布时间」（如 `邵泽慧 09-27 01:11`，
> 鼠标悬停看含年份的完整时间）；被退回的单在**「说明」列**里写「退回 09-27 02:10」，
> 方便判断这条单是刚发的还是早已过期，再决定要不要再次入池。

> **流转失败明细的搜索**：标题右边也有一个搜索框，用法和订单池、订单管理完全一样——客户微信 / 小红书账号 /
> 昵称 / 房间码 / 来源平台 / 游戏名 / 派单人 / 接单陪玩都能搜，空格分隔多个词表示同时满足；
> 搜过的结果框里会显示「筛选结果: 命中/总数」（2026-09-27 起）。这只过滤本页已经加载的单，不会把老单漏掉或删掉。

#### 管理端直添客户流转明细（客服养客的地方，2026-09-30 起两页合一）

**什么时候用**：客户在小红书 / 抖音上咨询了、也已经加到客服自己的**工作微信**上了，但**现在还不打**
（「就是客户现在不打，客服加到了客服自己的工作微信上了」）。这种客户**不要发单进抢单池**
——陪玩不会抢、还白占订单池，而是**先登记到这份明细里**（登记完是「待添加 / 待派单」那一档），
客服慢慢聊，等客户决定打了再从这一页一键派出去。

**两个入口**（老板要求「派单工作台 + 客户管理都能点」）：
- 派单工作台右上角的 **「直接添加客户」**（紫色主按钮，下面一行小字写着「只进客户流转明细，不打扰陪玩」）；
- 客户管理页右上角的 **「直接添加客户」**。

- 选择「入池」的订单出现在中栏的订单池，**不会**弹窗打扰陪玩
- 选择「广播」的订单同样进池，并立刻推送给本工作室所有在线、状态为「空闲 / 娱乐中」的陪玩（右下角弹窗）；到了「桥接工作室等待」时间（当前线上 5 分钟）后，这单会同步弹给桥接工作室同样条件的陪玩（弹窗标题为「🌉 桥接工作室发单！」），两边看到的是同一条单，桥接方也可以直接点「同意」抢单
- 选择「指定」的订单直接发送给指定陪玩的客户端，其他陪玩不会收到

**广播单怎么提醒，以及为什么有人会说「没弹窗」：**

广播 / 指定单推给**空闲**和**娱乐中**的陪玩 —— 娱乐中的人也能抢单，所以**一定会弹**；
只有**正在给别人打单**（接单中）的默认不打扰，他本人在「陪玩端 → 设置 → 打单中也接收新单弹窗」
里打开开关就会一起弹。提醒方式是三层叠加，任何一层都能把人叫醒：

1. 窗口里右下角的**抢单卡片**（停留时长 = 设置 → 派单 → 「新单弹窗秒数」，默认 20 秒）；
2. **提示音 + Windows 系统通知**（窗口在后台、最小化也有效）；
3. 客户端**窗口不在最前面**时，屏幕右下角会多一个**置顶小窗**（鼠标穿透，不挡游戏）；窗口就在眼前时只闪一下任务栏。

所以「发了单但没人弹窗」先按这三步核对：① 目标陪玩的状态 —— 空闲、娱乐中一定会弹，
接单中要看他有没有打开「打单中也接收新单弹窗」；② 他那台机器的客户端有没有连上
（服务端日志 `SEND order:urgent (broadcast)` 里有 `matched` / `connected` / `notConnected`
三个数，一眼能看出命中几人、真正在线几人，`byStatus` 还写明命中的人各是什么状态）；
③ 弹窗秒数是不是被设置调得很短。

### 5.4 入池方式（线下→线上流转 / 线上→线下流转）与线上 / 桥接单的「成不成」反馈

**发单时选「入池方式」（老板 2026-10-01 改名 + 改口径）**

发单弹窗里，派单方式只要**不是「指定」**（广播 / 入池）就会多一个下拉：

| 选项 | 效果 |
|------|------|
| **线下→线上流转**（默认） | 本店线下先抢 **3 分钟**（`设置 → 派单等待时间` 里可改）；没人接，才轮到**桥接工作室 + 线上俱乐部**（两边同时看见 —— 桥接没人接，线上马上能接） |
| **线上→线下流转** | **桥接工作室 + 线上俱乐部秒看到**（对外没有等待时间）；本店线下陪玩先看不见，过了 **5 分钟**没人接自动放给本店线下（客服也可以随时手动放，见下） |

下拉的默认值来自**你自己的入池方式档位**（「客服设置」里配的，见 §4.11）——不用每次手选。

选「线上→线下流转」的单，本店线下陪玩**先看不见**；在**订单管理**里状态后面会缀一个紫色小字：

- **「线上→线下」**：本店线下还看不见。**点一下这个紫字，就能把它放给本店线下陪玩**（会问一次「现在就放？」），
  放完本店陪玩马上能在订单池抢到。
- 你不点也没关系：过了 `设置 → 派单等待时间 →「线上→线下流转」线上先看多久、没人接才放给本店线下`（默认 **5 分钟**）
  会自动放行。
- **「已放给线下」**：已经放行了（你放的，或自动放的）。

**重新派单可以再选一次入池方式**

「订单池流转失败明细」里点**「再次发布」**，开出来的发单弹窗里**入池方式还能再选一次**（想换方式重发就换）。

**线上 / 桥接单要记「成不成」**

老板定的口径：派出去、被抢走都**不算业绩**——

- **本店线下的单**：陪玩点了「开始首单」就自动算成功，**不用你记**（点「记结果」会提示线下的单不用反馈）。
- **桥接 / 线上单**：**只有接单方反馈「成功」才算客服提成**。所以接单方给你回话后，你要回来记一笔：
  1. 在**订单管理**那一行的状态格里，线上 / 桥接单会缀一个小字：**待反馈（橙）→ 成功（绿）/ 不成功（红）**。
     **点这个小字**就能记；操作列那一格空着的时候，也会有一个**「记结果」**按钮。
  2. 弹窗里选 **成功** 或 **不成功**；选**不成功必须挑一个原因**
     （「客户对陪玩不满意 / 陪玩没接、放鸽子 / 时间对不上 / 价格没谈拢 / 客户临时取消 / 其他」，
     老板可以在「选项字典 → 反馈不成功的原因」里改），可以再写一句备注。
  3. 保存后状态格的小字当场变色，客服提成看板上的数字也跟着变（不成功的单**不计提成、也不扣钱**，
     但会留记录、进「原因排行」）。

**你自己的提成看板**

左侧菜单 → **财务管理 → 我的提成看板**（`/cs/finance/commission-today`）。和老板 / 店长看的是同一页：
整张表的人和数字都看得见，**点开明细只能点自己那一行**。看板的算法见 §4.11。

### 5.5 线下转桥接 / 线上统计（谁被接走了、应收多少、钱在哪）

派单管理 → **「线下转桥接/线上统计」** 这个标签页。

老板 2026-09-29 要的：「选择线下+线上入池的时候，线下没人接、被桥接工作室或者线上俱乐部接走，你**要做好统计、
并做好标注** —— 被桥接工作室接走的是**首单不结**的模式，记录好**机密还是绝密、应收多少、钱在哪里**等信息并做好
**汇总**；被线上俱乐部接走的，是按照**抽成**的模式」。

这页只统计**你按「线下→线上流转」发出去、本店线下没人接、最后被桥接工作室 / 线上俱乐部接走**的单
（已经接走但还没反馈结果的也算，方便你早点看到钱和去向）。每一行标出：

- **被谁接走**：桥接工作室 / 线上俱乐部（带工作室名字）；
- **结算模式**：桥接 = **首单不结**、线上俱乐部 = **抽成**；
- **机密还是绝密**、**单陪还是双陪**、**单量**（机密 / 绝密都一样：单陪 1 单、双陪 2 单）；
- **应收（客户流水）** =（主陪单价 + 搭档单价）× 时长（双陪要把搭档那份一起算上）；
- **应返还**：绝密单返还接单方 **15 元/人/小时**（双陪 ×2 = 30 元/小时）；机密首单不结、**不返还**；
- **工作室净得**：桥接按机密 35 / 绝密 30 元/人/小时，线上按 100 − 陪玩分成；
- **钱在哪里**：客服工作微信、客户付款账号、已经记过的资金流向（在「管理端直添客户流转明细」里记）；
- **结果**：成功 / 不成功 / 待反馈。

顶部是按月的**汇总**：被接走多少单（桥接 / 线上分列）、多少单量（机密 / 绝密分列）、应收合计、应返还合计、
工作室净得合计、已记流入 / 流出。右上角可以切月份。

**筛选与导出（2026-09-29 起）**

- **客服**：这页只给你看**你自己发的单**（右上角那块写着「只看我自己（你的名字）」）。服务端也拦着，
  就算手动改网址去查别人的，也看不到、更导不出来。
- **店长 / 老板**：右上角多一个**客服下拉**（默认「全部客服」），想看谁选谁、想导谁导谁。

  空一行后是**逐单明细**（时间 / 客户 / 客服 / 游戏 / 机密·绝密 / 单·双陪 / 被谁接走 / 去向工作室 / 结算模式 /
  单量 / 应收 / 应返还 / 工作室净得 / 钱在哪里 / 已记流入·流出 / 结果 / 备注）。
  文件带 BOM，**Excel 双击直接打开**（不要用记事本打开，会显示乱码），可以直接发给客服对账。

## 6. 角色操作指南：陪玩 (COMPANION)

陪玩不需要通过 Web 浏览器工作，而是使用专用的 Electron 客户端 桌面客户端。

### 6.1 安装与启动 Electron 客户端

1. 从管理员处获取 Electron 客户端 可执行文件
   （新电脑直接装装机包即可：`http://1.117.229.36:3001/api/agent/download/exe`，详见 §4.6.1）
2. 配置环境变量：
   - `AGENT_SERVER_URL`：后端服务器地址（默认云服务器 `http://1.117.229.36:3001`；客户端会把历史遗留的 `localhost` / 旧内网地址自动归位到云服务器，避免白屏）
   - `AGENT_TOKEN`：你的登录 Token
3. 运行 Agent 程序
4. 启动后 Agent 自动连接服务器，保持 WebSocket 长连接

**双击桌面上的「陪玩管理」图标没反应？（2026-09-23 起有专用修法）**

以前遇到过自动更新把客户端装成半残（目录里只剩 0 字节的文件、程序名都变成问号），双击图标就彻底没反应。
这种不用重装电脑、也不用等人到场，在这台电脑上右键「以管理员身份运行」下面这个：

```
http://1.117.229.36:3001/uploads/repair-companion.bat
```

它会自己把现场回传给我们 → 下载完整客户端 → 校验 → 换新 → 重装守护服务 → 重建桌面图标 → 把客户端拉起来。
顺带把这台电脑配成「可远程维护」状态（以后同样的毛病我们不用等人到场就能连进去看；**已经配好的电脑不会动账号和密码**）。
任何一步不合适它就停下，**不会**把你电脑里别的东西弄乱（只碰客户端自己的文件夹）。全程约 3~5 分钟，
因为要下载 120 多 MB。如果弹出「需要管理员权限」，点「是」即可。
跑完桌面图标就能正常双击了；要是黑窗口最后一行是报错，截图发给店长/客服，我们在后台能直接看到她这台机的现场。

**更新不用你操心：** 客户端每 30 分钟自己查一次版本，**正在接单时会自动跳过**，所以铺开是一步一步的 ——
隔天再看好几个人都升上去了是正常的，别急着让人重启电脑。

### 6.2 本地 Web 界面

Agent 启动后，在浏览器中打开 `http://localhost:9876` 可以看到本地控制面板：

**状态显示：**
- 当前模式（工作/娱乐）
- 工作时间计时
- 娱乐时间计时
- 总在线时长

**模式切换：**

- **工作模式 (WORK)**：切换后状态变为「在线 (ONLINE)」，可以接单
- **娱乐模式 (ENTERTAINMENT)**：切换后状态变为「空闲 (IDLE)」，暂时不接单

**状态不用自己记着切（系统自动跟单走）：** 陪玩登录后就是「空闲」；点「开始首单 / 续单 / 复购」、
或者接到单开始服务，会自动进入「接单中」；点「结束」（结束服务 / 完成订单）后**立刻**回到「空闲」，
不用再手动点一次切换按钮（同时挂两单时，两单都结束才回空闲；副陪也一样）。想休息打游戏时，
自己去点「娱乐」，状态变成「娱乐中」，这时不会被派新单。

**「续单 / 复购」只认你真的打得着的客户（2026-10-04，当天下午放宽了「自己名下」这一档）：** 在客户管理里点「续单 / 复购」时，
服务端会先查这个客户：**客户在你名下**（自己录入 / 自己打过的）→ 直接放行，哪怕还没有已完成单（老客户还剩存单也能直接打）；
**不在你名下** → 必须**真成交过**（有已完成单）**且你服务过**（当过主陪或副陪），否则挡住，
提示「只能续单 / 复购你自己服务过的客户」。所以在客户 B 那一行点续单 / 复购、或者拿别人的订单编号直接续单，
都会被拦下（客服 / 店长 / 老板代发不受影响）。
另外，**「续单」按钮只在同一个营业日（中午 12:00 为界）里有**：客户打了首单、当天 12 点前接着打才点得到「续单」；
过了中午 12 点，按钮就变成「复购」（另开一张复购单）。

**无操作会自动进「休息」并休眠（客户端 `1.0.20261015` 起）：** 出去吃饭 / 睡觉没关电脑的，客户端会自己发现——**每 65 分钟看一次**「鼠标键盘多久没动」，一看已经 60 多分钟没动，就认为人走了：先在右下角弹一条提示（同一套弹窗，游戏里也能看到，标题写着已经多少分钟没操作），20 秒后人还没回来就自动切到「休息」并休眠整机，省电也不空转。动一下鼠标或键盘就取消。
**「娱乐中」不会自动休息**（客户端 `1.0.20261016` 起）：开着娱乐出去，照常按 10 元/小时计费 ——
想停就自己切「休息」。自动休息只对「空闲」生效；「接单中」同样绝不会自动休息，正在给客户打的单不会被睡过去。

**娱乐门槛看的是「今天到手的钱」：订单流水 + 打掉的存单（2026-10-04 起）。** 娱乐随时能进，今天到手的钱够门槛
（线上 ¥300）就**免费**，不够就按 ¥10/小时计费。以前只算「今天新建订单的流水」，所以**整天在打老客户的存单**
（存单常常加在老的续单上打）会显示流水 0、娱乐照样收费 —— 现在**打存单的时长/金额也算进这个门槛**：
陪玩端顶部会写「今日¥X · 存单已打¥Y」，鼠标停在「娱乐」按钮上能看到「流水 + 存单 = ¥Z，够不够门槛」。

**按电源键唤醒后就是「空闲」，不用再点一下（客户端 `1.0.20261014` 起）：** 休息 = 整机休眠，人回来一动电脑（按电源键唤醒），
客户端发现状态还停在「休息」就自动切回「空闲」并同步服务端 —— 黑名单守卫、抢单、接单立刻按「空闲」口径走。
接单中 / 你自己切过的其他状态不会被改。

模式切换通过点击按钮完成，Agent 会立即同步状态到服务器。

### 6.3 订单通知与处理

当有新订单指派给你时，Agent 会通过 WebSocket 实时接收通知，本地界面会显示订单信息。

**订单处理流程：**

1. **收到订单**：本地界面弹出订单通知，显示游戏名称、金额、客户信息
2. **抢单**（池子订单）：在订单池中看到感兴趣的单子，可通过 Agent 点击「抢单」
3. **确认接单**：点击「确认」按钮，订单状态变为 CONFIRMED（已确认）
4. **开始服务**：点击「开始服务」后填写游戏模式、单价、实际时长，并上传客户转账截图；以上信息必填，系统据此计算审核金额并计入服务证据链
5. **服务过程留痕**：服务过程中按系统设置的截图阈值（截图间隔/首张延迟/黑屏判定/每小时期望张数）自动截图，本地保存、结束服务时上传；文件名带实际时间戳，黑屏截图会额外标记
6. **完成订单**：服务完成后点击「完成」，订单状态变为 DONE（已完成）
7. **结束服务对账**：结束服务时填写「客户实际转账合计（微信 + 支付宝，元）」，留空记为待核对；低于「填写时长 × 单价」会被标记异常供管理端复核，高于则不追责
8. **证据长图**：系统自动把「服务信息表 → 转账截图 → 游戏截图 → 财务核对卡 → AI 异常分析卡」纵向拼接成一张长图，供管理端按时间线比对

**抢到单之后不用自己切菜单：** 在订单池点「抢单」、或在右下角急单弹窗点「同意」抢到单后，界面会直接跳到「订单管理」，并弹出一张成功卡片（里面有客户微信、房间码，可一键复制），关掉卡片就能看到刚抢到的单。在订单管理里点「✅ 添加成功」（或「客户已同意」）后，界面会直接跳到「客户管理」，找到该客户点「开始首单」就能开工。整条链路是：订单池抢单 → 订单管理 → 客户管理，不用再手动点左侧菜单。

**自己录入的客户，四条路都给你（2026-10-04 起）：** 客户管理右上角「新建客户」录入的客户，
操作那一行**新客老客都由你自己挑**：

- 真新客 → 点「开始首单」（系统当场开一张首单直派单并开始计时，不用再去抢单池）；
- 本来就是老客 → 直接点「续单 / 复购」；
- 老客手里还剩没打完的存单 → 点「存单」把余额记上（**新建客户时也能一起填「客户存单余额」**），
  以后打这个客户默认走存单扣款；这个余额就是财务里「未打存单预留」的那个数，同一个数、自动同步。
  **扣多少以你「结束服务」时填的为准**（2026-10-04 起）：弹窗里会预填系统按计时算出来的金额，
  跟实际不一样就直接改成你自己的数（不填才用系统算的）；最多扣到存单余额为 0，不会扣成负数。
  **双陪也能用存单**（2026-10-04 起）：叫搭档一起来打这张存单，照样勾「用存单支付」，
  搭档接受邀请后一起打，结束时按你填的金额从客户存单里扣。

只要动过其中一条（开过单 / 记过存单），「开始首单」就自动收起来，只剩「续单 / 复购 / 存单」
（续单只在同一个营业日里给，过了中午 12 点只留复购）。

**订单卡片上的内部编号：** 订单卡片右上角那个 🆔 小图标，鼠标悬停才会显示「客户ID：…」这种系统内部编号；日常看客户微信号和昵称就够了，不用记编号。

**订单管理（接单记录）里的「我接的单 / 我发的单」（2026-09-27 起）：** 左侧菜单的「订单管理」是你的**接单记录**，
列表上方有个开关，默认停在 **我接的单** —— 也就是你抢到的、别人派给你的、以及你当搭档参与的单。
你自己发布过的订单（首单 / 续费 / 复购这类由陪玩发起、发布人就是你的单）点一下 **我发的单** 就能单独看
（页头标题也会跟着变成「我发的单」）；这些单如果也挂在你自己名下，**两个栏都会显示**，不会漏。

**客户来源（小红书 / 抖音…）你看不到（2026-09-29 起）：** 老板要求「陪玩端 隐藏 客户小红书信息」——
订单管理里的「客户账号」格、客户管理里的「来源 / 账号」列、订单详情弹窗里的「客户昵称 / 客户来源 / 来源账号」、
客户详情页的「平台」标签，**你这一端都不显示**（以前只是把来源账号抹成 `***`，留着「小红书」三个字你还是知道
这单从哪来）。这些来源信息只给**发这单的那家工作室**的客服 / 店长 / 老板看，
**桥接工作室 / 别家管理端一样看不到**（2026-10-02 起）。**你接单要用的联系方式不受影响**：客户微信、微信二维码、
房间码、YY / KOOK 都照常显示，抢到单就能看。

**发单时客服填的备注，接单记录里一眼可见（2026-09-29 起）：** 接单记录（订单管理）多了一列「备注」，
就是客服发单时在「备注」里写的那句话（客人对局的要求 —— 比如「只打机密」「老板朋友，态度好点」）。
一格一行，太长鼠标停上去看全。急单弹窗（还没点「同意」时）和「抢单成功」卡片上也会用橙色小字
「📝 备注：…」写出来，所以**抢之前就能看见**，不用等抢完；点开整行的订单详情里照旧有「备注」一栏。

**考勤现在覆盖三个职位，每个职位能单独关（2026-10-04 起）：** 「设置 → 考勤设置」里是 陪玩 / 客服 / 店长 三块，
每块一个「启用考勤」开关和上班 / 下班时间。**陪玩考勤默认关**（老板 2026-10-04：「陪玩是提成制、本来也不扣钱……
陪玩没必要考勤」）—— 哪个店想让陪玩也打卡，店长自己在「设置 → 考勤设置」里把「陪玩」那块打开即可（只影响本店）。
**陪玩**是客户端上线记上班、下线记下班（老口径不变，**开关打开后才生效**）；
**客服 / 店长**也是同一个客户端连接：客服端 / 店长端一上线自动打上班卡（晚于上班时间 = 迟到），
下线超过宽限期真的没连回来才打下班卡（早于下班时间 = 早退）——刷新页面、网络抖一下不会误记早退。
**管理端在「工资规则 → 考勤登记」里手动登记的一律优先**，当天填过（哪怕填的是缺勤）就不会被自动打卡覆盖。
三个职位的记录都在「考勤管理」里看（上半张是陪玩、下半张是客服 / 店长）；**陪玩考勤关着的时候，这一页只统计客服 / 店长，
陪玩那张表整块不显示，副标题会写明「本店没开陪玩考勤」。**
**首页看板（2026-10-04 起）**：老板 / 店长 / 客服的「首页 → 运营看板」多一张「🕘 今日考勤」卡片 ——
按职位（陪玩 / 客服 / 店长）分别列出**迟到 / 早退 / 未打卡 / 正常**，有问题的排在最前面；
还没到上班时间的人显示「未到点」，不算未打卡；某个职位考勤关掉了，那一块整块不显示。
**陪玩端首页**换成了进度条看板：今日 / 本月流水与单量、综合分·段位、今日剩余抢单名额、客户数
（**「今日考勤」只在陪玩考勤打开时才显示，默认关**），
加上我的 KPI 进度条（首单成功率 / 续单率 / 复购率 / 微信添加成功率 / 转化率 / 综合分与距下一级），
右边是**我的客户消费榜**（消费金额从高到低，进度条），一眼看完自己今天该盯谁。
某个职位暂时不需要考勤，就把它的开关关掉（**陪玩这一块默认就是关的**）：不记考勤，工资里的迟到 / 缺勤 / 早退扣款和全勤奖也都不参与
（考勤登记的员工下拉里也不再出现那个职位）。

**段位分 vs 综合分（2026-10-04 起）：**
- **段位分 = 最近 30 天流水 + 续单率 + 复购率 + 首单成功率** —— **段位只看这四项**（再叠加流水硬门槛）。
- **综合分 = 段位分 + 战绩图加分** —— 战绩图加分**不参与段位**，只用于排行榜 / 展示，而且**封顶**
  （默认最多 +10 分，可在「设置 → 评分与名额 → 战绩图加分上限」改，填 0 = 不封顶）。
- 为什么拆开：老板「如果陪玩 80 分……去上传几十张战绩图，这分岂不是一直维持在上等马上？全员都是上等马，
  岂不是就丧失评分系统的意义了」。所以**光靠传战绩图升不了段**，想升段只能把四项 KPI 做上去。

**段位分数怎么算（2026-10-04 起）：** 综合评分 = 最近 30 天流水 + 续单率 + 复购率 + 首单成功率 + 战绩图采纳加分。
前四项在「设置 → 评分与名额」里各配几条规则，写法就是「**达到 X 得 Y 分**」——
每一栏**只取达到的最高一档，不叠加**（例：流水 3000 得 20 分、6000 得 30 分、8000 得 40 分、10000 得 50 分 →
流水 10000 的人这一栏就是 50 分，不是 20+30+40+50）。现在的默认档位是：**最近 30 天流水** 3000 得 20 分 / 6000 得 30 分 /
8000 得 45 分 / 10000 得 50 分；**续单率、复购率** 过 30% 得 10 分 / 过 50% 得 20 分；
**首单成功率** 过 30% 得 5 分 / 过 50% 得 10 分。

**段位不只看分数，还看一条硬线（老板 2026-10-04）：**
- **最近 30 天流水没到「流水硬门槛」（默认 5200 元）的人，一律下等马** —— 其他分再高也不算，
  因为「挣不到钱就没给工作室创造价值」；
- 反过来，**流水达标的人最低也是中等马**（要的少、挣得少可以理解；要的少、挣得多才是最理想的陪玩）；
- 分数够「上等马线」（默认 85 分）才是上等马。
门槛和两条线都在「设置 → 评分与名额」里改，**门槛填 0 = 关掉这条硬线**。几个例子：
流水 8000 + 三率都过半 = 95 分（上等马，离 85 线还留 10 分缓冲）；流水 10000 只吃老客 = 90 分（上等马）；纯新客打满也只有约 4050 元、够不到 5200 门槛 → 必然下等马；
流水 6000 + 三率都过半 = 80 分（中等马）；流水 5000 + 三率都过半 = 70 分（**仍是下等马**，被硬线否决）。

**四项口径（2026-10-04 定稿）：**
- **流水 / 续单率 / 复购率 / 首单成功率** 统一按**最近 30 天**滚动统计（2026-10-04 起；原来流水按营业月、月初会全员短暂归零，现已改掉）。
- **续单** = 该客户在你这有**第 2 段及以后会话**（点「续单」加出来的那段），且**那段已打完（结束过）**；**复购** = 打完首单 / 续单后**隔了一个营业日**（12:00 为界）又来打。没结束的单、点了续单还没打完的段，一律不计（2026-10-05 起）。
- **续单率 / 复购率的分母都是「打了首单的客户数」**，两栏不互斥（隔天回头的客户两边都算）。
> **⚠️ 陪玩必看：不点「结束服务」，这一单就不算数（2026-10-05 起，网页 `v948`）。**
> 流水、首单成功率、续单率、复购率 **全都只统计「已经打完（结束过）」的单**。打完不点结束 =
> 这一单赚了多少、算不算成交，系统一概不知道：不计流水、不算首单成交、不算续单 / 复购，
> **分数和抢单名额都会少**。所以：① 陪玩端**首页看板最上面**常驻一条橙色提示；
> ② 「评分说明」弹窗顶部也写了一遍；③ 服务端**到点之后每 30 分钟再提醒一次**
> （右下角置顶横幅 + 铃铛，文案带「已经超时 X 小时 Y 分钟」），一直提醒到点了「结束服务」为止。

- **首单成功率** = **打完的首单客户数** ÷ **「添加成功」的客户数**（2026-10-05 起）。
  成交首单 = 这张首单**已经打完（结束过）**才算；点了「开始首单」但还在打的**不算**；
  加了微信却一直没打成的照样留在分母里 —— 这才叫「成功率」。
  （口径沿革：v932 曾经按「点了『开始首单』就算」，2026-10-05 老板驳回「我什么时候说过，不打完怎么算？」后统一成「只有打完才算」。）
- **纯新客上限（2026-10-04）**：抢单名额 3 单/天、单价最高约 45 元、每单约 1 小时 → 打满 30 天也只有约 4050 元，够不到 5200 门槛，**纯新客必然下等马**；想上高分只能靠老客（续单 / 复购不占每日名额）。
- **「续单」按钮只在同一个营业日里出现**：过了中午 12 点，即使单还挂着，客户管理里也只剩「复购」。

**每天能抢几单（每日名额制；2026-10-04 改成「抢单那一刻就扣」）：** 每个陪玩每天按段位发抢单名额
（默认上等马 3 个、中等马 2 个、下等马 1 个，店长可在「设置 → 评分与名额」按店改）。口径是：
- **在抢单那一刻就扣**，不再等「添加成功 / 转账」——防止有人一直不点添加成功就一直抢；
- **陪玩自己发布的单不占**（没消耗工作室资源）、**客服直接指定的单不占**（客服主动挑人，不走池子）；
- **线下工作室的预约单也占 1 个**（线上俱乐部的预约单不占）；
- 今天没抢完的**自动累计**到以后（今天剩 1 个，明天就是 3+1=4 个）；
- 抢单失败（没抢到 / 单被取消）名额**自动退回**。

订单池里那张卡片直接写「今日抢单名额：已用 X 个 ｜ 当前可用（含累计结余）Y 个」，
点「**点开看每天加/用明细**」能看到**最近 14 天每天加了多少、用了多少**，以及最近 20 笔明细
（每日发放 / 抢单扣减 / 抢单失败退回 / 补单返还 / 人工调整）。名额用完点「抢单」会提示
“今天的抢单名额用完了（XX N 个/天，没用完的会累计）；可以等明天，或让客服直接指定派单”。

**陪玩点「添加失败」→ 管理端补单（2026-10-04）：** 陪玩把客户加上却没通过时点「**添加失败**」，
系统自动生成一条**补单申请**（带失败原因 + 你上传的截图；同一张单只留一条，已经同意过的不重复开）。
管理端在「**订单管理 → 🧾 补单审核**」里看：
- **同意补单** → 这个陪玩的抢单次数 **+1**（写一笔台账）；**驳回**只留痕、不返还；
- **双方都有实时提示（2026-10-04）**：陪玩一提交，本店客服 / 店长 + 老板的右下角就弹一条、铃铛里留一份、
  「补单审核」的红点立刻刷新（不用再等 60 秒轮询）；管理端一点「同意」或「驳回」，**陪玩本人立刻收到提示**
  （同意绿色、驳回橙色并带上管理端写的备注），点通知直接跳到「订单管理」。
  以前只有管理端干等红点、陪玩被驳回了都不知道，现在两边都看得见。
- **核查最多提醒两次，然后就结案（2026-10-04 简化）**：同意后 **24 小时**，那条申请会出现在「**到期核查**」页签并带红点：
  管理端去回看“这个客户后来到底通过了没有”。确认通过了点「**客户后来通过了**」，**系统自动把这张单改成「已添加」并把客户归到这个陪玩名下**；
  还没通过点「**仍未通过**」→ **再等 7 天**提醒你一次；第二次再点「仍未通过」就**结案**，不再排提醒、也不再占红点
  （谁点的、什么时候点的都留档）。老板口径：「别搞这么复杂，先 24h 提醒一次，后期直接 7 天提醒一次。」
  客户哪天真通过了，随时去「客户管理」把他捞回来就行。

**订单池里灰色的单是什么（2026-09-21 起）：** 订单池现在分成两段。上面是可抢的新单（正常颜色，
点「抢单」就能接）；下面多了一段「今天已发过的单（灰色 = 已被抢走）」——今天发出去、已经被别人抢走的单
会灰掉留在列表里，不能点，右侧写着「已被 XX 抢走 / ✅ 你已抢到这单」和抢单时间。这样你一忙、或者刚好
在看视频没看到弹窗，也能回头看到「今天其实发了这么多单」，不会以为工作室没单。灰色单里**不带客户的
微信、也不带来源平台和来源账号**——那是别人的客户，抢到单的本人才能看到。

**同一个微信不能抢同一个客户（2026-09-29 起，2026-10-02 补齐）：** 老板定的口径是「每个陪玩绑定一个微信，说白了就是
同一个微信不能抢同一个客户」。所以：**你现在绑的这个工作微信已经接过这个客户**（你当过搭档的双人局也算），
再碰到他的单点「抢单」会被拦下并提示「你的工作微信「你的微信号」已经接过这个客户了，换新的工作微信后可以再接」。
**换了新的工作微信就可以继续抢**；同一个微信抢别的客户、别的陪玩用别的微信抢这个客户，都照常不受影响。
（注意：判重只认微信，不认人 —— 你换回原来的微信号，那条老账还在。）
**没绑工作微信 = 抢不了单（2026-10-02 老板方案 B）。** 没绑的人在订单池顶部会看到一张红卡片，
点「抢单」会被拦下并提示「还没绑定工作微信，现在抢不了单；请让店长 / 客服到「工作微信 → 陪玩工作微信」
帮你绑定后再抢」。绑定在管理端「工作微信 → 陪玩工作微信」由店长 / 客服操作，绑一个生效一个，绑好后立刻能抢。
**现在也可以自己填**：陪玩主页最上面有「📱 我的工作微信」卡片，填上你的号点「提交审核」，
管理端通过后就生效、立刻能抢（详见 6.3.2）。
**同一个客户可以发好几张单**（同一个客户问了工作室好几个矩阵账号，客服一条一条发，这是正常的）：
判重按**客户微信号**把这几个单算成同一个客户（不按客户档案编号 —— 客服每发一张单就会新建一条档案），
所以这几张单要由**不同的工作微信**接走。
**客服指定给你的单不算抢**：客服把池子里的单指定给某人、或者你「接受指定单」，都不走这条判重 ——
客服主动挑人（老客户回头想点回原来那个陪玩）要能派得出去。

**抢了不打单会被收回去：** 抢到单 180 分钟（3 小时）内没点「开始服务」、而且这单没有任何服务记录，
系统会自动把单退回订单池让给别人（**名额不退**）。所以抢单前确认自己这单能打；发布超过 24 小时的单
系统会直接作废并通知客服。

**新单只弹 Windows 桌面横幅（15 秒），可以点进去抢（老板 2026-10-01）：** 新单不再弹软件里那张右下角卡片，
改成只弹一个**置顶的 Windows 横幅**（横幅默认鼠标穿透，不挡你点游戏），**15 秒自动消失**；
鼠标移到横幅上它就变成可点，**点一下 = 把客户端拉到最前 + 打开抢单池 + 把这一单整行标黄 15 秒**。
**点横幅不会直接抢单** —— 老板定的规矩：「万一谁打游戏 误点了呢」，弹窗只把你送到池子里，
抢不抢还是你自己点那下「抢单」。弹窗秒数由老板在系统设置里配（`pool.popup_seconds`，线上 15 秒）。

**打不打搅你，你自己定：** 你是「**空闲**」或「挂机（休息）」时，新单**一定会弹**，不受设置影响；
只有**接单中**（正在给别人打单）与**娱乐中**可以自己关：「陪玩端 → 设置 → 通知」里的
**「打单中也接收新单弹窗」**（默认关）和**「娱乐中也接收新单弹窗」**（默认开）。
万一弹窗错过了也没关系：急单会直接出现在订单池里，且广播单对你所在工作室是**立即出现**、不用再等 60/120 秒。

**群聊广播提醒：** 客服在工作室群聊里发广播时，你的电脑屏幕右下角会弹出一个红色提醒窗口（📢 + 客服名字 + 内容），置顶显示 5 秒后自动消失，不会抢你的键盘鼠标焦点，打游戏或最小化了客户端也能看到。看到广播后如果想接这单，回群聊回复客服即可；广播内容也会留在工作室群聊里，可以随时回头翻看。

### 6.3.0 订单管理：我抢到的 / 我服务的 / 我发布的（2026-10-03 起）

陪玩端点进 **订单管理**，上面是三个页签：

- **我抢到的** —— 我自己在抢单池抢下来的单。
- **我服务的** —— 我在打 / 打过的单，包括「我是主陪」，也包括**别人邀请我当搭档（我是副陪）**的单。
  老板报的「王甲振被邀请打这个订单，为什么没给他生成接单记录」就是指这一类 —— 单其实一直在他名下，
  只是以前没有单独成栏，现在归到「我服务的」里。
- **我发布的** —— 我自己发的单。

> **客户信息保护（重要）：** 在「我服务的」里，**如果我不是这单的主陪**（是受邀搭档），
> 这一单的**客户微信号和二维码会被抹掉**，只留房间码 / YY / KOOK 这类执行必需的信息 ——
> 客户是主陪的客户，不能因为搭档过就拿到客户微信。
> 管理端（老板 / 店长 / 客服）看到的订单管理不受影响，还是完整的，并且可以按主陪 / 副陪筛选。
>
> **三个页签上带数量（2026-10-03，网页 `v882`）：** 页签会显示各自有几单（例如「我抢到的 3 / 我服务的 1 / 我发布的 2」），
> 被别人邀请来的单不会再藏在没点过的那一栏里 —— 老板报的「被邀请方打的这个订单找不到」就是为了这个。

### 6.3.1 把卡住的单转让给别人（转让订单）

陪玩端已经**没有「超过 180 分钟自动退回抢单池」这回事了**（老板 2026-09-29 拍板：「是谁抢的就是谁的」）。
单卡在自己手里、客户加了很久没通过、或者客户不满意时，由**陪玩自己**把单转给同事 —— 但**不是点一下就转过去**
（老板 2026-10-03：「想转让的订单，需要被转让方同意才能过来，要不然乱套了」）：

1. 打开「订单管理 → 我接的单」，在这张单的操作列点**「转让」**
   （也可以点整行打开「订单详情」，弹窗底部同样有「转让订单」）。
2. 在弹窗里选一个**同工作室**的陪玩（下拉里不会出现你自己），原因可选（默认会带出「客户一直没通过」，
   可以改可以清空）。
3. 点**「发出转让申请」** —— 这时只是**问他愿不愿意接**，单还在你名下：
   - 对方这边**不用等弹窗**：这张单会直接出现在他的「订单管理 → 我接的单」里，那一行写着红字「🔁 XXX 想转给你」，
     他点绿色**「接手」**单才真的过去（点红色「拒绝」就退回）；陪玩端右上角 🔁 铃铛里也留一份，在别的页面也能点；
   - 他点「拒绝」，单一直在你名下；
   - **30 分钟没人回应**自动作废（单也在你名下）；
   - 等着的这段时间，那一行的「转让」按钮会变成**「撤回」**（鼠标停上去看「在等谁同意」），点一下就能撤回、再换个人问。
4. 对方点了「同意」之后：
   - 这张单归**新陪玩**，他要重新加客户微信（联系进度会归零），会立刻收到一条「有人把订单转让给你」的提醒；
   - **你自己的接单记录里这张单不会消失**，那一行的操作列会写明
     「已转让给 XXX（2026/9/29 23:47）」；
   - **客户管理**里这条服务记录的「主陪」变成新陪玩，并标一个橙色的「已转让」，鼠标停上去能看到
     「什么时间、从谁转给谁、什么原因」。

注意：
- **已经开始服务的单不能自己转**（已经打过首单 / 有会话），要换人请联系客服走「归属调整」；
- 只能转给本工作室、没离职的陪玩；转给自己、转给不存在的人都会被拒；
- **只有被转让方能点「同意」**：申请的编号在谁手里都点不动别人那条（接口会拒「这条转让申请不是给你的」）；
- 转让记录（`OrderTransfer`）是留痕，不会被删 —— 谁转过、什么时候转的、转给谁，事后都查得到。
  没被同意过的申请不算转让，不会写进留痕。


### 6.3.2 我的工作微信（自己填，管理端审核后生效）

老板 2026-10-02 起：**工作微信可以自己填、以后想换也可以自己换**，但要**管理端审核通过才生效**。

1. 打开陪玩端主页，最上面有一张「📱 我的工作微信」卡片。
2. 卡片上写清楚现在**生效**的号（没绑就是红字「还没绑定 · 现在抢不了单」）、正在**审核中**的号、
   以及上一次被**驳回**的原因。
3. 在输入框里填上你自己在用的微信号，点「提交审核」（**换号也是这一步**）。
4. 管理端通过后，卡片上的生效号就变成新的（最多 30 秒自动刷新，切回窗口也会刷新）。
   **审核通过之前，系统（包括抢单判重）用的还是你现在这个号。**

注意：提交的号如果已经绑给别的陪玩、或者被客服占用，会当场提示提交不了，需要换个号或找管理端核实。
**没绑工作微信 = 抢不了单**，所以新来的先把这个填上（管理端通过后即可）。

### 6.3.3 客户看板：我的客户花了多少、现在在跟谁打（陪玩端，2026-10-03 起）

> 路径：左侧菜单 → **我的客户 → 客户看板**

- 这里**只有你自己的客户**（客户管理里归到你名下的），别人家的不会出现。
- 每一行写清：客户编号 + 状态、**消费金额**（只算**已完成**的单）、**今日（营业日）**一列（今日消费 + 今日单数 + 今日时长）、**完成单数**、**累计时长**（已完成会话时长之和）、
  最近一单时间，以及**现在是不是正在打**（正在打的红点闪烁，带游戏名、单号、已打多久、主陪 / 搭档是谁）。
- 这里是**进度条排行榜**（2026-10-04 起）：一个客户一条进度条，按「**累计消费**（默认）/ 今日消费 / 游戏时长」
  **从高到低**排下来，条形越长 = 数值越高，前三名带 🥇🥈🥉；点任意一行直接进这个客户的详情。
- 顶部一排数字：客户总数 / 正在打 / 今日消费 / 累计消费 / 累计时长（没有「陪玩数」——这里只有你自己）。
- **你看不到**客户是从哪个平台 / 哪个引流账号来的 —— 那是管理端的信息，不是不给你，是本来就不该给陪玩看。
  客户微信你自己心里有数：这里默认打码（避免挂墙 / 录屏泄露），需要时点右上角「显示微信号」。
- 数据 15 秒自动刷一次，正在打的时长按秒走字。

### 6.3.4 搭档邀请（别人请你一起打）：横幅点一下 → 订单管理里同意

有人指定你当搭档、或者在工作室里**广播找搭档**时：

- 你的电脑右下角会弹出一条**横幅**（和客服发单那条是同一种，游戏中也能看到），文案写清是谁邀请你、
  什么游戏、搭档金额和时长，下面一行提示「**点这里 → 打开订单管理，同意搭档邀请**」。
- **点一下横幅**：客户端会把自己拉到最前，并直接打开**订单管理**页（老板 2026-10-03：「改用客服广播的那种弹窗，
  陪玩点击就能跳转到软件的订单管理，然后去同意邀请」）。
- 订单管理**最上面**会出现一张 **「🤝 待我确认的搭档邀请（N）」**卡片，每条写明
  `谁邀请你 · 游戏 · 金额 · 时长` 和 `⏳ 还剩几秒自动取消`：点 **「同意」** 开始计时并入单
  （这单会出现在你的「我服务的」里），点 **「拒绝」** 退回、不影响主陪。
- 在别的页面时，右上角 **🤝 铃铛**里也留了一份，点开同样能同意 / 拒绝（兜底入口）。
- **不再**弹以前那种「Windows 系统通知 + 软件内模态框」两份了 —— 点了不跳转的那条已经删掉。
- 邀请**有效期 3 分钟**（2026-10-03，网页 `v882`）：这 3 分钟里点同意 / 拒绝都算数。就算超时没点，
  **这一单也不会被作废** —— 只是撤掉「待搭档」，主陪可以直接单人开打、也可以再邀请你一次
  （以前超时会把整段会话结束，主陪只能重新开一单，被邀请方的接单记录里就什么都不剩）。

### 6.3.5 实时看板（陪玩端）：谁在忙、谁快打完了、可以约谁

> 路径：左侧菜单 → **派单管理 → 实时看板**（2026-10-04 起）

老板原话：「这个看板也给陪玩端加上，让他们清楚知道其他人在干什么，可以提前跟快结束订单的人预约；
把桥接工作室的也加进来，但是不显示他们挣了多少，只标注订单信息。」

- 跟管理端同一张「一人一格」的看板，但你能看到的是 **本店同事 + 桥接工作室的陪玩**
  （本店之外的人会标 **🌉 桥接 · 工作室名**）。
- 每格写清：谁、什么状态、在打什么游戏、**跟谁一起打**、**已经打了多久**（按秒走字）、单号、客户编号。
  看到谁快打完了，就提前找他约下一场（走「搭档邀请」那一套，见 6.3.4）。
- **钱只显示你自己的**：只有你自己那一格是「今日业绩 / 本单金额」，别人的一格一律 **「🔒 业绩不公开」**，
  同店同事也一样 —— 看板是用来看谁有空、好约人的，不是拿来看别人挣多少的。
- 桥接工作室的人也只显示订单信息，看不到他们挣了多少（老板要求）。
- 顶部 5 个数（接单中 / 娱乐中 / 空闲 / 休息 / 离线）**点一下只看这一类**；数据 15 秒自动刷一次。

### 6.4 报账提交

**时间口径（全系统只有这一种）：每天中午 12:00 换日。** 中午 12 点前打的单、报的账都算**前一天**的
（9/20 中午 12 点前报的账算 9/19；10/1 中午 12 点前报的账算 9/30）。

1. 进入报账页面，页面顶部选**营业日**（默认今天，可往前选）
2. 页面上列出这一天你已完成、且**还没报过**的场次（已报过的不会重复出现）
3. 勾选要报的场次、填写报账金额、上传**一张微信收款总截图**（微信一张就够，不用分别传；
   可以直接 Ctrl+V 粘贴，或把图片拖进那个框）
4. 提交后报账进入「待审核」，等管理员审核

**我的报账微信码：** 报账页顶部有一块「我的收款码」——**第一次上传一次就行**（点「上传我的收款码」选图，
或点一下那个虚线框后 Ctrl+V 粘贴微信二维码截图，也可以把图片直接拖进去），财务审核时点开你这行的「收款码」就能拿手机扫给你，
不用再等你发码。换了微信号回来点「换一张」重新传即可，管理端能看到你最后一次换码的时间。

**漏报不用怕：** 昨天（或更早，最多 14 天内）忘了报，点报账页的「补报漏单」，
系统会把漏报的场次列出来让你补报——不再有「一过零点就报不了账、直接丢单」的问题。

**金额可以留空：** 结束服务时金额留空记为「待核对」，不影响报账；但**如果系统按真实计时算出来的金额
和你上报的差太多**，管理端会收到提醒，且你的报账单上会写清差额、相关场次会被标红（供管理端复核）。
这不是扣钱，是防止私单，老老实实填就没问题。

**能取多少钱（可支取余额）：** （当月累计业绩 × 你的分润比例）− 当月已支取 − 当月待审支取 − 未打存单预留。
其中**未打存单预留**= 你名下客户存单里**还没打完的余额，原样全额押着**（不打折）；只有**已经打完**的部分才按你的分润比例算进可支取。存单每打完一笔，预留就自动减少。
按月重置，存单没打完的部分会先替你扣住（防「冲完成绩跑路」）。

管理员可通过「远程控制」页面对你的电脑执行以下操作：

- 网络限速/解除限速

## 7. 核心工作流

### 7.1 订单全生命周期

```
客服创建订单
    │
    ├── 入池抢单 (POOL) ──▶ 订单进入订单池
    │                           │
    │                    ┌──────┴──────┐
    │                    │             │
    │              陪玩抢单 (grab)   客服指定 (assign)
    │                    │             │
    │                    └──────┬──────┘
    │                           │
    └── 指定派单 (DIRECT) ──────┘
                │
          状态: GRABBED
                │
          陪玩确认接单 (confirm)
                │
          状态: CONFIRMED
                │
          陪玩完成服务 (complete)
                │
          状态: DONE
                │
          陪玩提交报账
```

**状态转换规则：**

| 当前状态 | 可转换到 |
|----------|----------|
| PENDING（待处理） | GRABBED（已抢单）、CLAIMED（客服认领）、CANCELLED（已取消） |
| CLAIMED（客服认领） | PENDING（放回抢单池）、CANCELLED（已取消） |
| GRABBED（已抢单） | CONFIRMED（已确认）、CANCELLED（已取消） |
| CONFIRMED（已确认） | DONE（已完成）、CANCELLED（已取消） |
| DONE（已完成） | 不可转换（终态） |
| CANCELLED（已取消） | 不可转换（终态） |

**订单类型说明：**

| 类型 | 标识 | 说明 |
|------|------|------|
| 新单 | NEW | 新客户首次下单 |
| 续费 | RENEW | 老客户续费 |
| 复购 | REPURCHASE | 老客户再次购买 |
| 打赏 | TIP | 客户额外打赏 |

## 8. 常见问题 (FAQ)

### 客户端自动更新

**Q: 为什么别人升到新版本了，我这台还是旧版本？（老板 2026-10-03 问过）**

不是「网络排队」四个字打发过去的事，两个原因都修了（陪玩端 `1.0.20261006` + 服务端）：
1. **下载名额全网只有一个**（怕几台一起下载把办公室那条网占满，别的陪玩接口像掉线）。以前被叫到号的机器
   晚一步没抢到名额就直接放弃、要等 30 分钟，排队位置还被服务端吃掉 —— 所以有的机器一直轮不上。
   现在拿不到名额会自己重试；服务端叫号时**先把名额留给被叫到的那台**，3 分钟不来领才让给别人。
2. **开机时的检查以前会因为「正在接单」整轮跳过**，错峰还最多 2 分钟。现在照样检查，等接单结束再装
   （接单中绝不打断），错峰最多 10 秒，之后每 15 分钟再查一次。
   **开机 10 分钟内（`1.0.20261010` 起）：** 开机时机器上没人开打，上一单残留的「接单中」不再拦更新 ——
   直接把已经下好的包静默装上；这就是老板要的「每次开机就给他们更新」。

**Q: 装更新会打断我正在接的单吗？**

不会。状态是「接单中 / 服务中」时一律不动手，等这一单结束才下载安装；后台「推送更新」也是先等空闲。
**唯一的例外是「刚开机」**（系统启动 10 分钟内，`1.0.20261010` 起）：开机那一刻不可能有人在打单，
这一步直接把已备好的包装上，不占用你的接单时间。

**Q: 我点了邀请 / 转让的横幅，为什么没跳转？（老板 2026-10-03 报过）**

看那台电脑的客户端版本。能点击跳转的横幅要客户端主进程认「横幅动作」（`1.0.20261008` 才有）——
网页面虽然一直是最新的（从服务器加载），但「点了跳转」这一下是客户端主进程干的，老版本点了没反应。

> **搭档邀请（2026-10-03，网页 `v881`）：** 邀请搭档 / 广播找搭档的横幅也统一走这条路 ——
> 点一下直接打开「订单管理」，在最上面那张「🤝 待我确认的搭档邀请（N）」卡片里同意 / 拒绝；
> 以前那条「Windows 系统通知 + 软件内模态框」的组合已经删掉（见 6.3.4）。

旧版本之所以一直升不上去，以前是因为**连下载都要等陪玩空闲**：一单打十几个小时的那台机器，
永远轮不到更新（王甲振那单从 10-02 20:51 打到 10-03 中午，他那台就一直是 `1.0.20261007`）。
`1.0.20261009` 起改成：**接单中也先把更新包下好**（下载不打断接单），
只有最后「退出重启换文件」那一下等空闲 —— 这一单刚打完就立刻装，备货包下次开机也认，不用重下。
`1.0.20261010` 再补上「开机就装」：只要系统刚启动 10 分钟内，就直接把备好的包装上（残留的「接单中」不再拦它），
所以就算一整天都在打单，第二天一开机也会自动升到最新版。

### 杀进程（进程黑名单）

**Q: 我在「进程黑名单」里给某个人单独开了，为什么他那台电脑没反应？**

先看三件事：
1. **本店开关**（「进程黑名单」页顶部）有没有拨；只有「按人单独设置」里被**单独开**的人才不受本店开关限制。
2. 那个人在管理端显示的**状态是不是「空闲」** —— 黑名单是**按状态**生效的（本页下方「状态黑名单」配的是哪个状态就只在哪个状态动手）。
3. 他那台电脑的**陪玩端客户端**有没有开着并且登录着 —— 现在是「进程一启动就杀」（客户端里常驻监听器，
   不用等 10 秒轮询），但动作还是客户端做的，客户端没开着 / 没登录就不会动手。

> 2026-10-03 修掉的一个坑：陪玩端守卫以前要求**本机本地**记着「空闲」才动手，而这个本地值只有陪玩本人
> 在客户端点过状态（或解锁屏幕）之后才会写。重装 / 重启后没点过状态的机器就会一直不动手，
> 表现就是「老板在后台开了，那台机器没反应」。现在服务端会把真实状态一起下发，**本地没记过状态的机器跟着服务端走**；
> 本地明确选了「娱乐中 / 休息」的仍然以本地为准（不会被服务端补推的「空闲」覆盖掉）。
> 这条修复在**服务端**，不需要客户端升级就能生效。

**Q: 我接了单（或者接受了搭档邀请），为什么游戏一启动就被杀掉、一直玩不了？（老板 2026-10-03 问过）**

这是 2026-10-03 修掉的一个 bug，服务端升级后不会再出现。

原因：黑名单是按**状态**生效的（本店配的可能是「空闲时结束三角洲」这类），而陪玩端**只在收到服务端的
`blacklist:update` 时才知道自己现在是什么状态**。「接单中」这个状态只能由服务端自动给（开始服务、
接受搭档邀请 —— 陪玩本人点不出来），可服务端以前改完状态**没有通知客户端**：客户端还以为自己是「空闲」，
就把「空闲才杀」那条名单继续挂着，游戏刚启动就被自己的看门狗结束掉，看起来就是「接了单却不让玩」。

现在：接受搭档邀请 / 开始服务时，服务端**当场**把「接单中」推给相关的人（主陪、搭档都推），
该停的杀进程守卫立刻停掉。这条修复在**服务端**，客户端不升级也生效；已经卡住的那台机器，客户端重连一次即恢复。

**Q: 杀进程的时候那个人能看到提示吗？**

看得到。从陪玩端 `1.0.20261004` 起，杀黑名单进程会在**屏幕右下角弹一个置顶小窗**（跟群聊广播、新单提醒同一套，
全屏打游戏时也压在最上层），成功显示「已结束黑名单进程：xxx」、失败显示「没能结束…（原因）」。
同一个进程 3 分钟内只提示一次，不会一直闪。更早的版本用的是 Windows 系统通知，**「专注助手」开着或者全屏打游戏时会被系统吞掉**，
所以看不到提示 —— 升级到 `1.0.20261004` 即可。

### 无操作自动休息（休眠）

**Q: 我人在工位上但一直没碰电脑，会不会被自动休眠？**

会。客户端**每 65 分钟检查一次**，看到「已经 60 多分钟没动」就认为人走了：先弹提示、20 秒后自动休眠
（所以实际入睡时间大约是离开后的 65～130 分钟，取决于上次检查的时间点）。看视频 / 挂着不动也算无操作，
不想被休眠就随手动一下鼠标（客户端 `1.0.20261015` 起改成这个频率，以前是每分钟检查一次）。

**Q: 我开着「娱乐」模式出去了，会自己进休息吗？**

不会（`1.0.20261016` 起）。娱乐中不会自动休息，会一直按 10 元/小时计费 —— 要走就自己先点「休息」再走。
自动休息只对「空闲」状态生效。

**Q: 接单中会不会被自动休眠？**

不会。只要有进行中的服务会话（连副陪也算），服务端一律拒绝自动休息，客户端拿到拒绝就不休眠。手动点「休息」的旧规矩也没变（娱乐中不能直接点休息）。

**Q: 休眠后按电源键唤醒，还要自己点「空闲」吗？**

不用（`1.0.20261014` 起）。唤醒后状态还是「休息」的话，客户端会**自动切回「空闲」**并同步服务端，
直接就能接着抢单 / 接单。（接单中被叫醒的情况不会发生 —— 接单中根本不会自动休眠。）

### 账号与登录

**Q: 登录时提示"用户名或密码错误"怎么办？**

检查用户名和密码是否正确。如有疑问联系管理员重置密码。

**Q: 登录时提示"账号尚未通过审核，请联系管理员"？**

CS 和 COMPANION 角色的账号需要由老板审批后才能登录。请联系老板在「客户端授权」页面进行审批。

> 已办理离职的账号（陪玩 / 客服 / 店长都一样）不能再次登录；系统会在登录、刷新登录态和后续接口校验时
> 直接拦截，并提示“该账号已离职，无法登录”。点错离职可以在「员工管理」里点「恢复在职」救回来
> （已清零的余额、已交回的工位和工作微信不会自动还原）。
> 另外：**离职的人不会再被算成「待审核」** —— 离职会停用账号，而停用和待审核以前共用同一个标记，
> 导致离职的人一度又冒回「实名审核」列表和侧边栏红点里（2026-09-27 修）。离职的人也不会再出现在
> 「客户端授权」的待审核页签、以及绑定工作微信时的客服下拉里。

**Q: 为什么我在另一台电脑登了同一个客服 / 管理账号，这台就被踢下线了？**

这是刻意的（老板 2026-10-01 定的口径：「**客服 / 管理顶号，陪玩不顶**」）。
一个客服 / 管理账号**同一时间只能在一台电脑上在线**：新的登录会把旧的那台踢下去，
旧的那台会回到登录页并提示「该账号已在别的电脑上登录」。
**为什么这台不会自动登回去**：因为那样两台电脑会互相顶来顶去、谁都用不了。真要用这台电脑，
**手动**输密码点一下「登录」即可（手动登录会把另一台踢下去）。
**陪玩账号不受影响**：你的号可以在多台电脑同时在线，抢单弹窗照旧。

**Q: 忘记二次密码怎么办？**

联系老板在后台重置二次密码。当前版本不支持自助找回。

**Q: 登录时提示「too many request」（操作太频繁），是怎么回事？**

同一个人**一分钟内连续输错 5 次密码**就会触发这个提示，**等 1 分钟再试**即可，账号本身没问题。

> 2026-09-21 起限流改成**按账号**记账：以前整条宽带共用一个额度，一个人输错密码会把整个工作室都锁住；
> 现在只影响输错的那一个账号，别人照常登录。

忘记密码不用找店长：在登录页点**「忘记密码」**，填**你的登录姓名 + 身份证号**，自己设一个新密码（至少 6 位）。

**Q: 登录后能同时打开多个页面吗？**

可以。Token 存储在浏览器的 sessionStorage 中，同一浏览器新标签页需重新登录。

**Q: 登录后多久会自动退出？**

Access Token 有效期为 15 分钟，Refresh Token 有效期为 7 天。Token 过期后自动跳转登录页。

### 订单与派单
**Q：抢到单之后不动，会不会被系统自动收回去？**
A：**不会了**。老板 2026-09-29 拍板删掉了「抢单超时自动回收」（原来 180 分钟不动就退回抢单池），
现在**是谁抢的就是谁的**。如果客户加了很久没通过、或者客户不满意，由**接单陪玩自己**在接单记录里点
「转让」把单转给同事（见 6.3.1）；已经开始服务的单只能让客服走「归属调整」。转出去的单会留在原陪玩的
接单记录里并标明「已转让给谁、什么时候转的」，客户管理里同样看得到。**管理端「订单管理」列表里还单独有
一列「转让记录」**（2026-10-03 加的）：转过的单一眼就是红字「已转让」，鼠标停上去看「什么时候谁转给谁」，
不用再点进订单详情去找。

**转让还要对方点头（老板 2026-10-03：「想转让的订单，需要被转让方同意才能过来，要不然乱套了」）**：
点「转让」只是**发出申请**，被转让方在自己电脑上点「同意接手」单才真的过去；他拒绝、你撤回、
或者 30 分钟没人回应，单都一直留在你名下（申请会自动作废）。你在等待期间那一行的按钮是「撤回」。



**Q: "入池"、"广播"和"指定"有什么区别？**

- **入池**：订单进入公共订单池，陪玩自己在池子里看到并抢单，先到先得，不会弹窗提醒
- **广播**：订单进池的同时，本工作室所有在线、状态为「空闲 / 娱乐中」的陪玩电脑右下角立刻弹出抢单窗口（接单中的陪玩默认不弹，看本人设置），适合需要马上有人接的单；如果这单同时向桥接工作室开放，桥接工作室同样条件的陪玩会在「桥接工作室等待」时间到后收到同样的抢单弹窗
- **指定**：客服或管理员直接把订单发给指定的陪玩，只有他一个人会收到弹窗，其他陪玩看不到

**Q: 怎么看某个单是哪个工作室接的？**

订单管理列表里的「主陪 / 副陪」列就是这个用途：本店陪玩接的单只显示陪玩名（如「钱鸿鸣」）；**桥接工作室的陪玩接的单会显示紫字「桥接·光耀电竞」**，一眼就能区分。有副陪时显示「主陪+副陪」。鼠标悬停这一格能看完整说明，点开订单详情还能看到接单工作室。

**Q: 客户端是不是一直在后台跑、很占资源？**

为了省电省流量，客户端做了这些收敛：连接用 WebSocket 长连接（不是每秒发请求），断线后逐步退避到最多 60 秒重试一次；前端版本检查 5 分钟一次、更新检查 30 分钟一次（紧急更新仍可用后台「推送更新」立即下发）；日志只保留最近 14 天并自动清理。

**Q: 发布后客户端多久会更新？**

在线客户端最迟 5 分钟内自动更新并重启；**正在接单的会跳过，等这单服务结束再更新**，不会打断计时和截图。

**Q: 陪玩可以自己发订单吗？**

可以。陪玩端（客户端里的网页界面）也能点「发布订单」自己建单——陪玩自己拉到的客户、或者临时补单，不用再回来找客服。

**Q: 订单可以取消吗？**

只有状态为 PENDING（待处理）或 GRABBED（已抢单）的订单可以取消。已确认或已完成的订单不可取消。

**Q: 为什么我看不到某些订单？**

不同角色看到的数据范围不同：
- 客服只能看到自己创建的订单
- 陪玩只能看到分配给自己或自己抢的订单
- 管理员可以看到本工作室所有订单

**Q: 池子里的订单为什么没有陪玩接？**

确认是否有空闲（IDLE 或 ONLINE 状态）的陪玩在线。陪玩需要在 Agent 客户端中切换到「工作模式」才能接单。

**Q：为什么我点了「抢单」抢不了？**
A：看订单池里的「今日抢单名额」卡片：**抢单那一刻就扣**（不再等添加成功），
每天按段位发（默认上等马 3 / 中等马 2 / 下等马 1，店长可按店改），没用完会累计到以后，
点「点开看每天加/用明细」能看到每天的加/用和最近明细。自己发的单、客服指定单不占名额；
线下工作室的预约单也占 1 个。抢单失败名额会自动退回；客户没通过可以让管理端「同意补单」把次数还给你。
名额用完就去抢不用名额的单，或者等明天。

**Q：为什么有时候不弹新单窗口？**
A：你「空闲」或「娱乐中」时一定会弹（娱乐中也能抢单）。只有你**正在给别人打单**（接单中）
才默认不打扰 —— 想一边打单一边留意新单，去「陪玩端 → 设置 → 打单中也接收新单弹窗」打开即可。
另外新单都会进订单池，错过弹窗不等于错过单子。

**Q：为什么客户端偶尔收不到弹窗、过一会儿又好了？**
A：以前登录令牌 15 分钟过期后，客户端拿着旧令牌重连会被服务端直接拒，那段时间一条弹窗都收不到。
现在系统会自动换新令牌再连（服务端也给了 7 天宽限），正常情况下不会再出现这种断续。

### 财务管理（对账 / 提成 / 分成 / 风险）

> 路径：左侧菜单 → **财务管理**

财务模块统一以「整数分」存储金额、以每日 12:00 为营业日边界，老板/店长/客服均可查看，写入（新增规则、运行结算）限老板/店长。

- **价格规则**：配置机密/绝密的首单底价与续单/复购区间；陪玩可在底价之上上浮报价。
- **提成结算**：配置客服/店长提成规则（按认领流水比例或按单固定），点击「计算当月提成」生成幂等月度结算。
- **月度分成**：**只有线下工作室走阶梯**（线上俱乐部是按人固定比例）；阶梯明细以「设置 → 分成阶梯」里填的为准，
  **最高一档要入职满 6 个月**（没满回落下一档，勾「老员工」可豁免），运行后生成不可变结算快照。
  「设置 → 分账规则」下方的**线上俱乐部（固定比例）**只在建店时选了「线上俱乐部」模式（RENTAL / FIXED）的店才用；
  那一栏**显示的数字就是实际生效的数字**，改完记得点「保存」才会写进系统。
- **四个人分流水**（工作室 / 店长 / 客服 / 陪玩）：**全部在「设置 → 系统配置 → 利润分成（分账规则）」一页填**
  —— 陪玩按流水阶梯 / 线上俱乐部固定比例、**店长**（线下 / 线上分开）、**客服**（线下按流水比例、线上按每单固定金额），
  工作室拿剩下的。店长比例填了就会在月度提成结算里真的计提（草稿状态，可在「提成结算」页确认）；
  多位店长按人数均分；不填（0）就等于店长暂不参与分成。四栏加起来不允许超过 100%。
  （2026-09-22 合并：以前「利润分成」「客服设置」「财务中心」三处都能改同一批数，现在只有这一页能改。
  「利润分成」独立页、以及「客服设置」里那两行只读副本都已**删除**；
  「财务中心」保留一处只读展示 + 一个「去「利润分成」修改」按钮。）
- **「分账规则」一页看清四个人的比例**（2026-09-21 改版）：页面从上到下依次是
  **陪玩 → 店长 → 客服 → 工作室**，横向一列就是一个流水档位。陪玩按档填、店长和客服各一格（全店统一、
  不随档位变化）、**工作室是灰底只读、系统自动算**（= 100 − 陪玩 − 店长 − 客服），每个档位各算一个数，
  所以永远填不出「加起来 120%」。档位卡片的表头可以直接改「最低流水 / 最高流水」，右侧垃圾桶删档，
  最下面「+ 添加流水档位」加档；四个数超过 100% 时页面会红条报警、点保存会被拒绝并给出算式。
  线上俱乐部那一块按同一套四行排（陪玩固定比例 / 店长按比例 / 客服每单固定金额 / 工作室自动）。
  页面最下面的「桥接工作室」块放**机密 / 绝密单价**和**首单返款**（首单 = 第一个小时，机密填 0 即不返还，
  绝密按小时返、双陪 ×2）—— 这两组数原先分别散在「财务中心」和「派单与提成」，2026-09-22 合并到这里。
- **左侧栏直接显示工资比例**：「财务管理 → 陪玩工资管理 / 客服财务管理」和「设置中心 → 客服设置 / 工资规则」

  **首单** 机密 35 / 绝密 45，**续单 / 复购** 机密 40 / 绝密 60（老板 2026-10-04：「机密续单/复购 40-60 是正常的，

它会：把客户端里的服务器地址全部改回云端（改前留 `.bak` 备份）→ 把服务器地址加进「不走代理」名单 →
换装最新客服端 → 修好桌面图标 → 开通远程管理通道 → 把这台电脑报进「设置中心 → 客户端与设备 → 机器管理」。
跑完桌面上会出现「客服管理」图标，点开就是登录页。**如果打开还是老样子**：先把 VPN / 加速器退掉再点一次；
再不行把 `%TEMP%\chunlv-repair-cs.log` 发给管理员。
（只想让管理员先看看现场、不想改任何东西：双击同一个链接，或让管理员在「机器管理」里点「一键诊断」。）
**Q：左侧栏的图标颜色、卡片上的彩条是什么意思？**
A：只是区分模块和指标，不影响功能 —— 左侧导航按模块上色（首页紫、派单青、订单蓝、客户紫、员工橙、
财务绿、店铺粉、设置灰），顶栏的**门店名胶囊**（如「蠢驴电竞」）告诉你当前在哪家店；
首页四张指标卡（昨日总流水 / 全月总流水 / 在线陪玩 / 待审核）各自的颜色只是为了区分数字。
「设置 → 分账规则」里的四行也各自有固定色：**陪玩紫、店长蓝、客服橙、工作室绿**。

**Q：店长改了分成比例，为什么别的店没变？**
A：这是设计如此。店长保存的是**本店覆盖**（`StudioConfig`），只影响自己这家店；
老板保存的才是**全站默认**。店长没填过的项，自动跟着老板的默认值走。
如果店长想回到老板的默认值，设置页提示条上有「全部恢复默认」。

**Q：店长改了设置，页面上提示「部分全局项未改动」是什么意思？**
A：说明这一次保存里混进了「全站只有一份」的配置（例如 AI 密钥、语音服务器凭据、
客户端与网页版本号），这些只有老板能改。系统**存下了你能改的部分**，并把跳过的键列出来告诉你，
避免你以为是保存失败了。

**Q：店长到底能改本店的什么？**
A：**默认是全部**。只有两类例外：① 密钥 / 凭据（AI、实名认证、语音中转）；
② 一份值绑住全站的版本号与服务器参数（客户端与网页版本号、连接宽限期）。杀进程只剩**本店**那一个开关 `blacklist.enabled`，是店长自己拨的，不在老板专属名单里。
除此之外的配置 —— 钱、派单、截图阈值、考勤时间、评分线、异常阈值、选项字典、平台账号类型、
通知偏好 —— 都由店长在自己店里填，只影响本店。

**Q：老板怎么知道哪家店自己改了配置？**
A：用老板账号打开**设置中心 → 系统配置**，绿色提示条上有门店下拉框，
选一家店就能看到它自定义了哪些项，可以逐项恢复，也可以整店恢复。

**Q: 不同角色能看到对方的数据吗？**

系统按工作室和角色进行数据隔离：
- OWNER 可查看所有数据
- ADMIN 可查看本工作室的所有数据
- CS 只能看到自己创建的订单
- COMPANION 只能看到与自己相关的订单

**Q: 如何修改员工角色？**

联系老板在「员工管理」页面编辑员工信息。

**Q: 客户端最小化/缩到托盘后，界面还会自己刷新吗？**

不会。界面被切到后台（窗口最小化、被其它窗口完全挡住、切到别的应用）时，所有列表类的自动刷新都会停下来，
不再发请求；把窗口切回前台会自动继续按原来的节奏刷新。这样这些整天挂在托盘里的客户端不会白白占带宽和 CPU。
聊天消息走的是长连接，不受影响；订单池、人员列表这类「自动出现」的东西，切回前台时可能还是几秒前的样子，
点一下刷新或等一小会儿即可。

**Q: 怎么知道对方看没看到我发的消息？**

只有**你自己发出去**的消息，气泡下面会有一行小字：

- 灰色「未读」＝ 对方还没打开这个会话；
- 绿色「已阅读」＝ 对方已经打开了这个会话（对方一打开就实时变，不用刷新页面）。

别人发给你、你还没看的消息不显示这行字；**群聊里也不显示**（群里人多，单条已读没有意义）。

**Q: 客服 / 店长 / 老板 在人员列表里怎么算「在线」？**

看两个信号，取更新的那一个：① **客户端连接还在不在**——客户端开着，哪怕窗口最小化、收进托盘，
也算在线；② 客户端每 60 秒上报一次的心跳。两个信号都没有、超过 **5 分钟**，才显示离线
（陪玩是 2 分钟，因为陪玩端每 30 秒就报一次心跳）。真的把客户端退掉、或者电脑断网才会变离线。
窗口从最小化切回前台时会立刻补报一次，不用等满一分钟。

**Q: 打语音通话，界面显示「已接通」但两边都没声音，是怎么回事？**

这是 2026-09-21 修掉的老问题，根因在网络上，不是谁的设备坏了：以前语音是「双方电脑直连」，
需要网络帮两边打一个洞。但办公室/家宽这条线是**多线**的（实测同一台电脑几分钟内先后变成两个不同的公网
IP），出口一变洞就废；服务器上也没有可用的中转（云安全组没放通相关端口）。所以表现就是时好时坏、
显示接通却没声音。

现在改成**声音从服务器中转**（走客户端本来就连着的那条长连接），不再依赖打洞：
- 一般通话质量不受影响；网络抖动时软件会提示「对方网络抖动，正在重连…」，**接通的那通电话不用重打**，
  恢复后声音自动接上（实测断网 6 秒后双向声音自动恢复）；
- 断网期间不会把旧声音攒着，避免重连后突然喷出几秒前的声音。

注意：**网页版（http:// 开头的地址）拿不到麦克风**（浏览器安全限制，必须 https），
所以语音通话请**用客户端**发起和接听。

**Q: 怎么确认语音通道是好的（不用麻烦陪玩反复试）？**

在客户端/网页里按 F12 打开控制台，输入下面这行，就会自己发起一通到对方的测试通话：

```js
window.__chunlvVoice.startCall('<对方userId>', '测试')
```

通话中执行 `window.__chunlvVoice.stats.current` 可以看到 `sentFrames / receivedFrames / playedFrames`
（发了多少帧、收到多少帧、播放了多少帧）。**playedFrames 一直在涨 = 声音确实在放**；
如果 sentFrames 涨、playedFrames 不涨，说明对方没收到（多半是对方网络断了，看服务端日志里那条
「Voice call」记录即可）。

**Q: 可以添加更多工作室吗？**

可以。老板在「工作室管理」页面可创建多个工作室。

**Q: 陪玩端「动不动掉线 / 自己闪一下重新加载」是怎么回事？**

以前确实有这个问题：服务端每一次重启（我们每发一次版都会重启），陪玩端下一轮心跳就会把页面刷一次，
看起来就像掉线。现在修好了 —— 服务端重启不会再让任何客户端刷新；只有**真的发布了新前端**才会自动刷一次，
而且**正在接单 / 服务中的陪玩不会被刷**，要等这单结束、下一轮心跳才更新。
另外普通网络抖动导致的断开，服务端有 60 秒宽限期：60 秒内连回来就当作没掉过线，状态和弹窗都不受影响。
如果某个陪玩端还是反复掉线，先看两点：① 他客户端里存的是不是很旧的登录凭证（让他退出重新登录一次）；
② 他那边的网络 / 杀毒软件是否在拦 WebSocket，把客户端日志发我们查。
